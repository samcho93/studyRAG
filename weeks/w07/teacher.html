답은 문서셋에 있는데

Q. RAG 수업은 무슨 요일 몇 교시이고 어느 강의실인가?
A. 제공된 근거 문서에서 찾을 수 없다.

정답: 화요일 1-3교시, 305호 — 2학기 시간표 문서에 있다

범인은 누구인가? LLM · 프롬프트 · 검색 · 청킹 · 문서

발문: “다섯 용의자 중 누구를 제일 먼저 조사하겠나?” 손을 들게 한다. 대부분 LLM을 고른다.

답은 오늘 데모에서 확인한다(검색: 근거 청크가 6위라 top-3 밖). 칠판에 다섯 용의자를 적어 두고 데모 뒤에 동그라미 친다.

두 단계: 색인과 질의

색인 · 한 번

문서 → 청킹 → 임베딩 → 벡터스토어

문서가 바뀔 때만 다시. 느려도 된다

질의 · 매번

질문 → 임베딩 → 검색 top-k → 프롬프트 → LLM

빨라야 한다. 비용은 대부분 LLM 호출

연결 고리: 같은 임베딩 모델 (e5면 passage: / query: 접두어까지)

위젯 기준 실측 감: ③ 임베딩 37청크는 수백 ms~수 초(WebGPU/WASM에 따라), ④ 검색은 수 ms, 실제 LLM 호출은 1~3초.

발문: “문서가 하나 추가되면 어느 단계를 다시 돌려야 하나?” → 그 문서만 청킹·임베딩해 add. 질의 쪽은 그대로.

모델을 바꾸면 색인 전체를 다시 해야 한다는 점도 짚는다(6주차 벡터DB 운영과 연결).

각 단계의 산출물

단계산출물기본 설정 값
① 문서 로드{ id, title, type, text }12개
② 청킹{ id, doc, start, end, text }37개 (재귀 200자)
③ 임베딩·저장{ id, vector, meta }37 × 384
④ 검색[{ id, score, meta }]top-3
⑤ 프롬프트{ system, messages }근거 [1]~[3]
⑥ 생성{ text, usage }답 + 인용 번호

“정상일 때 무엇이 나와야 하는지 알아야 비정상을 알아본다.” 산출물 모양을 외우라는 게 아니라, 각 단계 뒤에 console.log할 곳을 아는 것이 목적이다.

meta에 원문 위치(start/end)와 문서 id를 꼭 넣는 이유: 인용(11주차)과 hit 판정(오늘 C4)에 쓴다.

디버깅: 검색부터 확인한다

  1. ④ hit인가? 근거 청크가 top-k 안에 있나
  2. 없으면 몇 위인가? k 밖 → k·검색 방식 / 어디에도 없음 → ② 청킹 · ① 문서
  3. 있으면 ⑤ 프롬프트를 사람이 읽어 본다
  4. 그래도 틀리면 ⑥ 생성 (지시문 · 모델 · 온도)

LLM은 ⑤에 든 것만 본다. 근거가 없으면 어떤 모델도 못 맞힌다

왜 ⑥부터가 아니라 ④부터인가: ④는 결정적(deterministic)이고 싸다. 골든셋만 있으면 자동으로 판정된다. ⑥은 비싸고 매번 다르다.

4주차 칠판 문장 “검색 실패는 생성으로 복구되지 않는다”를 다시 가리킨다.

최소 구현: 질의 단계

async function answer(question, k = 3) {
  const q = await embed(question, { role: 'query' });
  const hits = store.search(q, k);                   // ④
  const prompt = ragPrompt(question,
    hits.map((h) => h.meta));                         // ⑤
  const { text } = await generate({
    provider: 'anthropic', ...prompt });             // ⑥
  return { text, sources: hits.map((h) => h.id) };
}

색인 단계까지 합쳐도 20줄 남짓 · 전체 코드는 학생용 페이지 3절

짚을 점 세 가지: ① 질문은 role: 'query'(e5 접두어) ② ragPrompt에 h.meta(청크 객체)를 넘긴다 ③ sources를 함께 반환한다. 답만 반환하면 추적이 불가능하다.

이 코드는 모델과 키가 필요해 워커에서 돌리지 않는다. 위젯이 똑같은 흐름을 돌린다.

데모 · 전체 파이프라인 실행

시연 순서 (단계별 결과는 오른쪽 실행 결과 창에 나온다)

  1. 처음 화면 q01: ①~⑥이 모두 초록. 단계별 시간을 읽고 색인과 질의의 시간 차이를 짚는다. 12칸 hit@3 = 11/12
  2. “✗ top-k=1: q03” → 1위가 FAQ 페이지의 저작권 문구 청크(broken-mixed). 근거는 2위. k=2로 올리면 hit
  3. “✗ 표 깨짐: q10” → 근거 청크 6위, miss. 3위의 시간표 청크는 머리글(요일 교시 과목 강의실 담당)뿐이다. 청크 크기 300 → 시간표가 한 청크가 되어 2위로 hit
  4. “✗ OCR 오류: q11” → 검색은 1위 hit인데 답이 “5O%”. 검색 문제가 아니라 ① 문서(파싱) 문제
  5. 모델을 all-MiniLM-L6-v2로 → hit@3이 약 4/12로 떨어진다. 프롬프트 형식은 같아도 근거가 틀리면 끝

수치는 Node(WASM, q8)에서 같은 설정으로 측정한 값이다. WebGPU(fp32)에서는 점수 소수점 셋째 자리가 조금 다를 수 있다. 키가 있으면 ⑥이 실제 호출로 바뀐다(수업 중 교사 키 입력은 화면 공유를 끄고 한다).

관찰 질문

  1. 색인(①~③)과 질의(④·⑤) 중 어디가 오래 걸리나?
  2. q03을 top-k=1로 — 1위 청크는 왜 올라왔나?
  3. q10 — 근거는 몇 위? 크기 300이면?
  4. q11 — hit인데 왜 틀렸나? 어느 단계를 고치나?
  5. 영어 전용 모델 — hit@3은? 프롬프트는?
  6. 문서셋에 없는 질문 — “찾을 수 없다”고 하나?

1~4는 짝 활동 20분, 각 짝이 답을 한 줄씩 적어 낸다. 5~6은 휴식 후 전체 토론.

2번 기대 답: 저작권·메뉴 문구처럼 모든 페이지에 붙는 상투 문구는 짧고 일반적이라 어떤 질문과도 적당히 가깝다 → 색인 전에 제거해야 한다(3주차 전처리).

4번 기대 답: ① 문서/파싱. 검색·생성은 제 일을 했다. “검색 성공 ≠ 정답”을 끌어낸다.

import { ragPrompt } from '/assets/js/core/llm.js';

function formatPrompt(question, contexts) {
  const sources = contexts
    .map((c, i) => `[${i + 1}] (${c.title}) ${c.text.trim()}`)
    .join('\n\n');
  return [
    '아래 근거만 사용해 답한다. 근거에 없으면 "문서에서 찾을 수 없다"고 답한다.',
    '문장마다 사용한 근거 번호를 [1]처럼 붙인다.',
    '',
    `근거 문서:\n${sources}`,
    '',
    `질문: ${question}`,
  ].join('\n');
}

  { title: '실습실 이용 규정', text: '한 사람이 연속으로 사용할 수 있는 시간은 최대 12시간이다.\n' },

];

왜: 번호는 인용의 열쇠다. 모델이 [1]이라고 쓰면 코드가 contexts[0]을 찾아 원문을 보여 줄 수 있다(11주차). 제목을 붙이면 모델이 “어느 문서의 말인지”를 알고, 사람도 프롬프트를 읽기 쉽다.

빈 줄 차이: ragPrompt는 청크 텍스트를 trim하지 않아 끝의 \n 때문에 [1]과 [2] 사이에 빈 줄이 두 줄 생긴다. 실제 결과에서 확인된다. 위젯은 넘기기 전에 trim한다.

부록 B · C2 정답

import { chunk } from '/assets/js/core/chunker.js';
import { BM25, tokenize } from '/assets/js/core/bm25.js';
import { ragPrompt } from '/assets/js/core/llm.js';

function mockGenerate({ messages }) {
  const [ctx, q] = messages[0].content.replace('근거 문서:\n', '').split('\n\n질문: ');
  const qt = new Set(tokenize(q));
  let best = { score: 0, text: '' };
  for (const src of ctx.split(/\n\n(?=\[\d+\] )/)) {
    const [, n, body = ''] = src.match(/^\[(\d+)\] ([\s\S]*)$/) ?? [];
    for (const sent of body.split(/(?<=[.!?])\s+|\n+/)) {
      const score = [...new Set(tokenize(sent))].filter((t) => qt.has(t)).length;
      if (score > best.score) best = { score, text: `${sent.trim()} [${n}]` };
    }
  }
  return { text: best.score >= 3 ? best.text : '문서에서 찾을 수 없다.' };
}

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const chunks = corpus.documents.flatMap((d) =>
  chunk(d.text, { strategy: 'recursive', size: 200 })
    .map((c) => ({ id: `${d.id}#${c.index}`, doc: d.id, text: c.text.trim() })));
const retriever = new BM25().add(chunks);

function answer(question, k = 3) {
  const hits = retriever.search(question, k);
  const prompt = ragPrompt(question, hits);
  const { text } = mockGenerate(prompt);
  return { answer: text, sources: hits.map((h) => h.id) };
}

for (const q of ['실습실에서 GPU 서버를 한 사람이 연속으로 쓸 수 있는 최대 시간은?',
  '성적 우수 장학금 지급액은?', 'RAG 수업은 무슨 요일 몇 교시이고 어느 강의실인가?']) {
  console.log(q, answer(q));
}

실행 결과: q01 → “…최대 12시간이다. [1]” (sources: facility-rules#1, broken-mixed#0, facility-rules#0) · q11 → “성적 우수 장학금은 직전 학기 평균 평 점이 4.0 이상인 학생에게 지급한 다. [1]” (지급액이 아니라 자격 문장을 골랐다) · q10 → “요일 교시 과목 강의실 담당 [1]” (시간표 머리글 청크가 1위).

왜: 색인(chunks, retriever)은 함수 밖에서 한 번, 검색·생성은 함수 안에서 매번. 학생이 answer() 안에서 청킹하면 동작은 하지만 질문마다 색인을 다시 만든다 — 이것이 두 단계를 구분하는 이유다.

    const [, n, body = ''] = src.match(/^\[(\d+)\] ([\s\S]*)$/) ?? [];
    for (const sent of body.split(/(?<=[.!?])\s+|\n+/)) {
      const score = [...new Set(tokenize(sent))].filter((t) => qt.has(t)).length;
      if (score > best.score) best = { score, text: `${sent.trim()} [${n}]` };
    }
  }
  return { text: best.score >= 3 ? best.text : '문서에서 찾을 수 없다.' };
}

const log = [];
async function step(stage, fn, summarize) {
  const t0 = performance.now();
  const out = await fn();
  log.push({ stage, ms: +(performance.now() - t0).toFixed(2), artifact: summarize(out) });
  return out;
}

import { chunk } from '/assets/js/core/chunker.js';

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const golden = await (await fetch('/assets/data/golden/golden.json')).json();

function evaluateBM25(size) {
  const chunks = corpus.documents.flatMap((d) =>
    chunk(d.text, { strategy: 'recursive', size })
      .map((c) => ({ id: `${d.id}#${c.index}`, doc: d.id, text: c.text })));
  const retriever = new BM25().add(chunks);
  const runs = golden.items.map((item) => {
    const ev = item.evidence[0];
    const relevant = chunks.filter((c) => c.doc === ev.doc && c.text.includes(ev.quote)).map((c) => c.id);
    const retrieved = retriever.search(item.question, chunks.length).map((r) => r.id);
    return { id: item.id, retrieved, relevant };
  });
  const mean = (f) => runs.reduce((a, r) => a + f(r), 0) / runs.length;
  return {
    size,
    chunks: chunks.length,
    'hit@1': mean((r) => hitAtK(r.retrieved, r.relevant, 1)),
    'hit@3': mean((r) => hitAtK(r.retrieved, r.relevant, 3)),
    'hit@5': mean((r) => hitAtK(r.retrieved, r.relevant, 5)),
    MRR: mean((r) => reciprocalRank(r.retrieved, r.relevant)),
    'miss@3': runs.filter((r) => !hitAtK(r.retrieved, r.relevant, 3)).map((r) => r.id).join(' '),
  };
}

console.table([100, 200, 300].map(evaluateBM25));
