청크가 100만 개라면?

100만 개 × 384차원 = 질의당 곱셈 3억 8,400만 번

  • Flat(전부 비교)은 항상 정확하지만 시간이 N에 비례한다
  • JS 실측: 128차원 · 1만 개 ≈ 2ms → 384차원 · 100만 개 ≈ 0.6초
  • 동시 사용자 10명이면? 서버는 이것만 한다

우리 문서셋은 청크 수십 개 — 그래서 지금까지는 문제가 없었다

근사 최근접 이웃(ANN) · HNSW

정확한 top-k를 거의 찾되 훨씬 적게 비교한다

Recall@k = |ANN ∩ 정확한 top-k| / k

놓친 청크는 뒤에서 되살릴 수 없다

L2 고속도로 → L1 → L0 골목길(모든 벡터)

각 층에서 “이웃 중 질의에 더 가까운 곳”으로만 이동, 막히면 한 층 내려간다

층이 오를수록 노드가 약 1/M로 줄어든다

학생용 페이지의 HNSW 그림을 함께 띄운다. 비유: 서울 → 부산을 갈 때 고속도로(L2)로 가까이 간 뒤 국도(L1), 골목(L0)으로 들어간다.

강조: 거리 계산이 N번이 아니라 수백 번. 위젯 기본 설정에서 3,000 → 약 217번(7%).

9주차 Recall@k와 구분한다: 오늘의 정답은 “Flat의 결과”, 9주차의 정답은 “골든셋 근거 문서”.

HNSW의 세 손잡이

파라미터뜻키우면너무 작으면
M노드당 이웃 수Recall↑ 메모리·구축↑그래프가 성겨 막힌다
efConstruction구축 탐색 폭품질↑ 구축 시간↑엉뚱한 이웃 연결
efSearch검색 후보 수Recall↑ 질의 시간↑첫 막다른 곳에서 멈춤

efSearch만 질의마다 바꿀 수 있다 → 구축은 넉넉히, 조절은 efSearch로

실무에서 흔히 쓰는 값: M 16~32, efConstruction 100~200, efSearch 50~100 (라이브러리마다 기본값은 다르다). 위젯은 브라우저 속도 때문에 M 12, efConstruction 48로 낮췄다.

위젯은 efSearch < k일 때 “잰 노드 중 가까운 k개”를 돌려준다. 라이브러리는 efSearch를 k로 올린다는 점을 말해 둔다.

데모 · Flat vs HNSW 속도 비교

시연 순서 (결과는 오른쪽 실행 결과 창에 실시간으로 나온다. 시간 수치는 컴퓨터마다 다르다)

  1. 처음 화면: N 3,000 · 128차원 · M 12 · efSearch 32 → Node 실측 기준 약 ×6~9, Recall 1.00, 구축 약 0.5초, 거리 계산 3,000 → 217
  2. efSearch를 한 칸씩 내린다 → efSearch 1에서 Recall 약 0.39 (빨간 판정). 0.9를 처음 넘는 지점을 학생이 찾게 한다(Node 측정: 10 → 0.88, 16 → 0.95)
  3. “실패: M 2” → 질의는 ×19로 빠른데 Recall 약 0.28. “빠른데 틀린 검색”이 가장 위험하다고 강조
  4. “실패: N 1천 · 32차원” → ×0.7, Flat 58µs vs HNSW 84µs(Node). 본전 질의 수 “없음”
  5. “실패: 무작위 분포” → 같은 파라미터로 Recall 약 0.58, 속도 ×2.7 수준. 구조 없는 데이터에서는 “이웃의 이웃도 가깝다”는 전제가 약하다. 0.9를 넘기려면 efSearch 128이 필요하고 그때는 Flat과 속도가 같다
  6. 시간이 되면 “큰 N: 2만 개” → 구축 약 7초(Node), 진행률과 ■ 취소를 보여 준다. efSearch 64에서 ×14, Recall 0.96

관찰 질문

  1. 거리 계산 비율(3,000 → 약 200)과 속도 향상이 다른 이유는?
  2. Recall이 0.9를 처음 넘는 efSearch는?
  3. M 2는 빠른데 왜 쓸 수 없나?
  4. N 1천에서 HNSW가 느린 이유 · 우리 문서셋엔 무엇을?
  5. 무작위 분포에서 Recall이 떨어지는 이유는?
  6. N이 커지면 속도 향상과 Recall은?

1~3은 짝 활동 10분, 4~6은 휴식 후 전체 토론.

1번 기대 답: HNSW는 거리 계산 외에 힙 정리, 방문 표시, 불규칙한 메모리 접근 비용이 있다. Flat은 연속된 메모리를 순서대로 읽어 캐시에 유리하다.

6번 기대 답: N이 커질수록 속도 향상은 커지지만 같은 efSearch의 Recall은 떨어진다. Node 측정(128차원, efSearch 32): 3천 개 ×7 · Recall 1.00 → 2만 개 ×20 · Recall 0.86. 규모가 커지면 efSearch를 다시 맞춰야 한다.

코드로 확인하기

// Flat 검색 시간은 N에 비례한다 (384차원, 질의 1개)
const DIM = 384;
function flatMs(n) {
  const data = new Float32Array(n * DIM).map(() => Math.random() - 0.5);
  const q = new Float32Array(DIM).map(() => Math.random() - 0.5);
  const t0 = performance.now();
  let best = -Infinity;
  for (let i = 0; i < n; i++) {
    let s = 0;
    for (let j = 0; j < DIM; j++) s += data[i * DIM + j] * q[j];
    if (s > best) best = s;
  }
  return performance.now() - t0;
}
flatMs(10000); // 워밍업
for (const n of [10000, 20000, 40000]) console.log(`N=${n}: ${flatMs(n).toFixed(1)}ms`);

▶ 실행 → Node 실측 N=10,000: 6.2ms · 20,000: 13.2ms · 40,000: 24.0ms. 두 배 → 두 배를 확인한다.

DIM을 768로 바꿔 다시 실행하면 또 두 배. “차원도 비용”이라는 점을 짚는다.

다른 근사 · 메타데이터 필터

IVF · PQ

IVF: k-평균 묶음 중 가까운 nprobe개만 뒤진다

PQ: 벡터를 조각내 1바이트 번호로 압축 (1,536B → 48B)

HNSW는 속도, PQ는 메모리 문제에

필터

후필터: top-k 뒤 거르기 → 0개가 될 수 있다

선필터: 조건 안에서 검색 → 근사 인덱스와 섞기 어렵다

IVF 비유: 도서관 서가. nprobe = 몇 개 서가를 둘러볼지. 경계에 꽂힌 책을 놓친다.

C5 결과를 미리 예고: guide 조건 후필터 → k=3 요청에 1개. pgvector도 HNSW 인덱스 검색 뒤 WHERE를 적용하므로 결과가 적게 나올 수 있다(0.8부터 iterative scan 옵션으로 보완). Qdrant는 탐색 중에 필터를 적용한다.

정리

  • 벡터스토어 = 벡터(찾기) + 원문(답·인용) + 메타데이터(거르기)
  • Flat은 정확하지만 N에 비례. 수만 개 이하면 Flat으로 충분
  • HNSW는 빠르지만 놓친다. 속도는 반드시 Recall과 함께 말한다
  • 필터는 후필터가 결과를 비울 수 있다

부록 B · C1 정답

// seeded random unit vectors (same every run)
function rng(seed) {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = Math.imul(a ^ (a >>> 15), a | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
function randomUnit(n, dim, seed) {
  const r = rng(seed);
  const out = new Float32Array(n * dim);
  for (let i = 0; i < n; i++) {
    let s = 0;
    for (let j = 0; j < dim; j++) { const x = r() * 2 - 1; out[i * dim + j] = x; s += x * x; }
    for (let j = 0; j < dim; j++) out[i * dim + j] /= Math.sqrt(s);
  }
  return out;
}

const N = 2000, DIM = 64;
const data = randomUnit(N, DIM, 1);
const query = randomUnit(1, DIM, 2);

function topK(data, dim, q, k) {
  const n = data.length / dim;
  const ids = new Int32Array(k).fill(-1);
  const scores = new Float32Array(k).fill(-Infinity);
  for (let i = 0; i < n; i++) {
    let s = 0;
    for (let j = 0; j < dim; j++) s += data[i * dim + j] * q[j];
    if (s <= scores[k - 1]) continue;          // not better than current 10th
    let p = k - 1;                              // insertion into sorted top-k
    while (p > 0 && scores[p - 1] < s) {
      scores[p] = scores[p - 1];
      ids[p] = ids[p - 1];
      p--;
    }
    scores[p] = s;
    ids[p] = i;
  }
  return { ids: Array.from(ids), scores: Array.from(scores, (x) => +x.toFixed(4)) };
}

// reference: score everything, sort, cut
function topKSort(data, dim, q, k) {
  const all = [];
  for (let i = 0; i < data.length / dim; i++) {
    let s = 0;
    for (let j = 0; j < dim; j++) s += data[i * dim + j] * q[j];
    all.push([i, s]);
  }
  return all.sort((a, b) => b[1] - a[1]).slice(0, k).map(([i]) => i);
}

const mine = topK(data, DIM, query, 5);
console.log('topK :', mine.ids.join(', '), '| 점수', mine.scores.join(', '));
console.log('정렬 :', topKSort(data, DIM, query, 5).join(', '));
console.log('일치 :', JSON.stringify(mine.ids) === JSON.stringify(topKSort(data, DIM, query, 5)));

기대 출력: topK : 1791, 1577, 1153, 1798, 196 | 점수 0.3736, 0.3694, 0.3614, 0.3462, 0.3461 · 정렬 결과와 일치 true.

왜 이렇게 푸는가: k등 점수보다 작으면 바로 continue — 대부분의 벡터가 여기서 끝나므로 전체 정렬(N log N)보다 빠르고 메모리도 k칸이면 된다. i * dim + j 인덱싱이 “벡터를 한 줄로 이어 붙인” 저장 방식의 핵심이다. FAISS의 Flat도 같은 구조다.

부록 B · C2 정답

function rng(seed) {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = Math.imul(a ^ (a >>> 15), a | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
const r = rng(7);
const DIM = 128, K = 10, QUERIES = 20;
const MAX_N = 32000;
const data = Float32Array.from({ length: MAX_N * DIM }, () => r() * 2 - 1);
const queries = Float32Array.from({ length: QUERIES * DIM }, () => r() * 2 - 1);

// top-k by dot product over the first n rows only
function topK(n, qo) {
  const ids = new Int32Array(K).fill(-1);
  const sc = new Float32Array(K).fill(-Infinity);
  for (let i = 0; i < n; i++) {
    let s = 0;
    for (let j = 0; j < DIM; j++) s += data[i * DIM + j] * queries[qo + j];
    if (s <= sc[K - 1]) continue;
    let p = K - 1;
    while (p > 0 && sc[p - 1] < s) { sc[p] = sc[p - 1]; ids[p] = ids[p - 1]; p--; }
    sc[p] = s; ids[p] = i;
  }
  return ids;
}

for (let w = 0; w < 3; w++) topK(MAX_N, 0); // warm-up: let the JIT compile before timing
const rows = [];
for (const n of [1000, 2000, 4000, 8000, 16000, 32000]) {
  const t0 = performance.now();
  for (let q = 0; q < QUERIES; q++) topK(n, q * DIM);
  const ms = (performance.now() - t0) / QUERIES;
  rows.push({ N: n, 'ms/질의': +ms.toFixed(3), 'ms/1만 개': +((ms / n) * 1e4).toFixed(2) });
}
console.table(rows);
const last = rows.at(-1);
console.log(`100만 개로 늘리면 약 ${((last['ms/질의'] * 1e6) / last.N).toFixed(0)}ms/질의 (선형 외삽)`);

import { recallAtK as coreRecall } from '/assets/js/core/metrics.js';

function recallAtK(approx, exact, k) {
  const truth = new Set(exact.slice(0, k));            // exact top-k = the "relevant" set
  const hits = approx.slice(0, k).filter((id) => truth.has(id)).length;
  return hits / k;
}

console.log('recall@5  =', recallAtK(approx, exact, 5));

// 2) a naive "approximate" search: look at only a fraction of the vectors
function rng(seed) {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = Math.imul(a ^ (a >>> 15), a | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
const r = rng(3);
const N = 5000, DIM = 32, K = 10;
const data = Float32Array.from({ length: N * DIM }, () => r() * 2 - 1);
const dot = (i, q) => { let s = 0; for (let j = 0; j < DIM; j++) s += data[i * DIM + j] * q[j]; return s; };
const search = (q, ids) => ids.map((i) => [i, dot(i, q)]).sort((a, b) => b[1] - a[1]).slice(0, K).map(([i]) => i);

const all = Array.from({ length: N }, (_, i) => i);
const rows = [];
for (const frac of [0.1, 0.3, 0.5, 0.9, 1]) {
  const part = all.filter(() => r() < frac); // random subset of the data
  let sum = 0;
  for (let t = 0; t < 50; t++) {
    const q = Array.from({ length: DIM }, () => r() * 2 - 1);
    sum += recallAtK(search(q, part), search(q, all), K);
  }
  rows.push({ '살펴본 비율': frac, 'recall@10': +(sum / 50).toFixed(3) });
}

// A tiny navigable graph in 2D (one HNSW layer). Node → [x, y]
const points = {
  A: [0, 0], B: [2, 2], C: [5, 1], D: [3, 4], E: [1, 5],
  F: [3, 7], G: [5, 6], H: [7, 5], I: [8, 2], J: [7, 0],
};
const graph = {
  A: ['B', 'C'], B: ['A', 'C', 'D', 'E'], C: ['A', 'B', 'J'], D: ['B', 'F'],
  E: ['B', 'F'], F: ['D', 'E', 'G'], G: ['F', 'H'], H: ['G', 'I'], I: ['H', 'J'], J: ['C', 'I'],
};
const query = [6, 5];
const dist = (id) => Math.hypot(points[id][0] - query[0], points[id][1] - query[1]);

// 1) greedy: move to the closest neighbor while it gets closer
function greedySearch(start) {
  let cur = start;
  const path = [cur];
  for (;;) {
    const best = graph[cur].reduce((b, n) => (dist(n) < dist(b) ? n : b), cur);
    if (best === cur) return { found: cur, path, evaluated: null };
    cur = best;
    path.push(cur);
  }
}

// 2) beam search: keep the ef best nodes seen so far, expand the closest unexpanded one
function beamSearch(start, ef) {
  const visited = new Set([start]);
  let results = [start];            // best ef so far, sorted by distance
  const expanded = new Set();
  let evaluated = 1;
  for (;;) {
    const next = results.find((id) => !expanded.has(id));
    if (!next) break;               // every kept node expanded → converged
    expanded.add(next);
    for (const n of graph[next]) {
      if (visited.has(n)) continue;
      visited.add(n);
      evaluated++;
      results.push(n);
    }
    results = results.sort((a, b) => dist(a) - dist(b)).slice(0, ef);
  }
  return { found: results[0], evaluated };
}

const truth = Object.keys(points).sort((a, b) => dist(a) - dist(b))[0];
console.log('정답(전체 비교):', truth, dist(truth).toFixed(2));
const g = greedySearch('A');
console.log('탐욕 탐색:', g.path.join(' → '), '| 도착', g.found, dist(g.found).toFixed(2));
for (const ef of [1, 2, 3, 4]) {
  const b = beamSearch('A', ef);
  console.log(`beam ef=${ef}: ${b.found} (${dist(b.found).toFixed(2)}), 거리 계산 ${b.evaluated}회 / 전체 ${Object.keys(points).length}`);
}

기대 출력: 정답 H(1.00). 탐욕: A → C에서 멈춤(4.12). C의 이웃 A(7.81)·B(5.00)·J(5.10)가 모두 C보다 멀다 = 국소 최적. beam ef=1 → C(거리 계산 4회), ef=2 이상 → H(10회).

왜: B(5.00)는 C보다 멀지만 D → F → G → H로 가는 길목이다. 후보를 2개 들고 있으면 “지금은 조금 멀어도” 그 길을 버리지 않는다. 이것이 efSearch의 역할이다. 이 작은 그래프에서는 ef=2가 전부를 보지만, 수천 개 그래프에서는 극히 일부만 본다.

import { VectorStore } from '/assets/js/core/vectorstore.js';

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();

// Toy embedding (no model): hash character bigrams into 256 buckets.
// Good enough to find documents that share words with the query.
function toyEmbed(text, dim = 256) {
  const v = new Float32Array(dim);
  const s = text.replace(/\s+/g, ' ');
  for (let i = 0; i < s.length - 1; i++) {
    let h = 2166136261;
    for (const ch of s.slice(i, i + 2)) h = Math.imul(h ^ ch.codePointAt(0), 16777619);
    v[(h >>> 0) % dim] += 1;
  }
  return v;
}

const store = new VectorStore();
for (const d of corpus.documents) {
  store.add(d.id, toyEmbed(d.title + ' ' + d.text), { title: d.title, type: d.type });
}

// post-filter: search first, then drop what fails the filter
function postFilter(q, k, filter) {
  return store.search(q, k).filter((r) => filter(r.meta));
}

// pre-filter: keep only matching items, then rank them all
function preFilter(q, k, filter) {
  const qv = store.search(q, store.size); // exact scores for every item (Flat)
  return qv.filter((r) => filter(r.meta)).slice(0, k);
}

const q = toyEmbed('검색 결과를 평가하는 지표 Recall과 임베딩, 벡터 인덱스');
const onlyGuide = (m) => m.type === 'guide';
const show = (rs) => rs.map((r) => `${r.id}(${r.score.toFixed(2)})`).join(', ');
console.log('필터 없음 top-3 :', show(store.search(q, 3)));
console.log('post-filter     :', show(postFilter(q, 3, onlyGuide)), '← k=3을 요청했는데');
console.log('pre-filter      :', show(preFilter(q, 3, onlyGuide)));
