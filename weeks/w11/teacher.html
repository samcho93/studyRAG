→ 이 답을 확인하려면 무엇을 해야 하나?

문서 전체(284자)를 읽어야 한다 → 아무도 읽지 않는다 → 출처는 장식이 된다

발문: “검색 엔진 결과에서 출처 링크를 눌러 본 적이 마지막으로 언제인가?” 대부분 안 누른다.

사람은 출처가 “있다”는 사실만으로 신뢰한다. 그래서 출처는 누르기 쉬워야 하고, 누르면 바로 그 문장이 보여야 한다.

인용처럼 보이는 거짓

…최대 12시간까지 사용할 수 있다 [1]. 사용 전 캘린더에 등록해야 한다 [4]. 주말에는 누구나 자유롭게 이용할 수 있다. 장비 고장은 조교에게 알린다 [2].

  • [4] — 출처는 3개뿐이다 (없는 번호)
  • 세 번째 문장 — 인용이 없다, 게다가 사실과 반대
  • [2] — FAQ 문서라 장비 고장 이야기가 없다 (엉뚱한 출처)

틀린 인용은 인용이 없는 것보다 해롭다

학생에게 30초 주고 “무엇이 틀렸나” 찾게 한다. 세 가지를 모두 찾는 학생은 드물다.

이 답변이 위젯의 “⚠ 실패 예시”다. 데모에서 다시 본다.

RAG 서비스 화면의 네 요소

요소하는 일설계 포인트
① 입력질문을 받는다예시 질문으로 범위를 알려 준다
② 답변문장마다 [n][n]은 키보드로 누를 수 있는 버튼
③ 출처청크 + 근거 구간문서 이름과 위치를 함께
④ 피드백👍/👎 + 틀린 문장모으면 골든셋이 된다

상태: 로딩 · 정상 · 거절 · 오류 · 검증 경고

“피드백을 받으면 무엇에 쓰나?” 발문. 기대 답: 틀린 답변을 모아 골든셋(9주차)에 넣고 다시 측정한다.

접근성: 인용 버튼에 aria-describedby로 출처 제목을 연결하면 스크린리더가 “[1] 실습실 이용 규정”으로 읽는다.

인용 형식 설계

형식장점약점
번호 [1]짧다, 정규식으로 파싱목록과 어긋날 수 있다
문서 이름사람이 읽기 좋다이름 매칭이 어렵다
원문 인용 「…」구간을 바로 찾는다길고, 모델이 고쳐 쓴다

규칙: 문장마다 · [1][2] 또는 [1, 2] · 근거 없으면 “문서에서 찾을 수 없다”

ragPrompt()의 시스템 프롬프트를 화면에 띄워 “문장마다 사용한 근거 번호를 [1]처럼 표기한다”를 보여 준다.

원문 인용 형식은 C4와 연결된다. 모델은 인용문의 띄어쓰기를 고쳐 쓰므로 원문에서 그대로 찾을 수 없다.

문장-근거 정렬

  1. 답변을 문장으로 나눈다 (“…다. [1]”의 [1]은 앞 문장)
  2. 문장마다 [n]을 뽑는다 — 출처 수보다 크면 없는 번호
  3. 청크를 문장으로 나눠 핵심어가 가장 많이 겹치는 문장을 고른다
  4. 문서 위치 = chunk.start + 청크 안 위치

289–320 = 213 + (76–107)

Q04 오버랩 질문의 예. 청크 #1이 213에서 시작하므로 청크 안 76번째 글자는 문서 289번째다.

검증 규칙(위젯): 숫자는 그대로 있어야 한다. 한글 단어는 2-gram 하나라도 있으면 “있음”. 핵심어 60% 미만 → 근거 불일치, 일부 누락 → 확인 필요.

위치를 청킹부터 유지해야 하는 이유

위치가 없으면 doc.text.indexOf(chunk.text)로 찾아야 한다 → 세 경우에 틀린다

  • 중복 문장: FAQ의 같은 Q&A 두 개 → 늘 첫 번째를 가리킨다
  • 정규화: “평 점이” → “평점이”로 고쳐 저장하면 원문에 없다
  • 제목 붙이기: “[실습실 이용 규정] …”은 원문에 없다 (4주차 C5)

벡터스토어 메타데이터에 { doc, start, end }를 함께 저장한다

4주차 C5에서 “원문 위치는 제목을 붙이기 전 기준을 유지해야 11주차가 깨지지 않는다”고 했던 것을 회수한다.

C4 2단계가 중복 FAQ 사례를 직접 다룬다: 전체에서 찾으면 54–70, 두 번째 Q&A 안에서 찾으면 141–157.

부록 B · C1 정답

const answer = '수료 요건은 출석률 80% 이상이다 [1]. 최종 발표도 통과해야 한다 [1][2]. 성적 비율은 [3, 4]를 본다.';

function parseCitations(text) {
  const nums = [];
  for (const m of text.matchAll(/\[(\d+(?:\s*,\s*\d+)*)\]/g)) {
    for (const part of m[1].split(',')) nums.push(Number(part.trim()));
  }
  return nums;
}

console.log(parseCitations(answer));
console.log('인용된 출처 번호(중복 제거):', [...new Set(parseCitations(answer))]);
console.log(parseCitations('인용 없음'), parseCitations('[12] 두 자리 [ 1 ]'));

실행 결과: [1, 1, 2, 3, 4], 중복 제거 [1, 2, 3, 4], 마지막 줄 [] [12].

왜: matchAll은 괄호 그룹 하나에 여러 번호가 있는 [3, 4]를 한 번에 잡으므로 안에서 쉼표로 다시 나눈다. [ 1 ]처럼 괄호 안쪽에 공백이 있으면 인용으로 보지 않는다 — 형식을 엄격하게 정해야 파싱이 쉽다.

부록 B · C2 정답

const SOURCE_COUNT = 3;
const answer =
  'GPU 서버는 최대 12시간까지 쓸 수 있다 [1]. 사용 전에 캘린더에 등록한다 [4]. ' +
  '주말에는 누구나 이용할 수 있다. 장비 고장은 조교에게 알린다 [2][0]. 문서에서 찾을 수 없다.';

const parse = (t) => [...t.matchAll(/\[(\d+(?:\s*,\s*\d+)*)\]/g)].flatMap((m) => m[1].split(',').map(Number));
const REFUSAL = /찾을 수 없|알 수 없|내용이 없/;

function checkCitations(answer, sourceCount) {
  const sentences = answer.split(/(?<=[.!?])\s+/).filter(Boolean);
  const invalid = [];
  const uncited = [];
  sentences.forEach((s, i) => {
    const nums = parse(s);
    for (const n of nums) if (!(n >= 1 && n <= sourceCount)) invalid.push({ sentence: i + 1, n });
    if (nums.length === 0 && !REFUSAL.test(s)) uncited.push(i + 1);
  });
  return { sentences: sentences.length, invalid, uncited };
}

const r = checkCitations(answer, SOURCE_COUNT);
console.log(r);
console.log(`검증 통과: ${r.invalid.length === 0 && r.uncited.length === 0}`);

실행 결과: sentences: 5, invalid: [{sentence:2,n:4},{sentence:4,n:0}], uncited: [3], 검증 통과: false. 5번째 “문서에서 찾을 수 없다.”는 거절이므로 uncited에 들어가지 않는다.

왜: [0]도 없는 번호다(번호는 1부터). 거절 문장을 빼지 않으면 올바른 거절 답변이 “인용 없음”으로 벌점을 받는다.

부록 B · C3 정답

const text = '조건식 a < b && c > d 는 참이다. 메모: <img src=x onerror=alert(1)> 는 문자일 뿐이다.';
const spans = [
  { start: text.indexOf('a < b'), end: text.indexOf('a < b') + 'a < b && c > d'.length },
  { start: text.indexOf('<img'), end: text.indexOf('> 는') + 1 },
];

function escapeHtml(s) {
  return s.replace(/[&<>"']/g, (c) => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' })[c]);
}

function highlight(text, spans) {
  let html = '';
  let last = 0;
  for (const { start, end } of [...spans].sort((a, b) => a.start - b.start)) {
    const s = Math.max(start, last); // overlapping spans: never go backwards
    if (end <= s) continue;
    html += escapeHtml(text.slice(last, s));
    html += `<mark>${escapeHtml(text.slice(s, end))}</mark>`;
    last = end;
  }
  return html + escapeHtml(text.slice(last));
}

실행 결과: 조건식 <mark>a &lt; b &amp;&amp; c &gt; d</mark> 는 참이다. 메모: <mark>&lt;img src=x onerror=alert(1)&gt;</mark> 는 문자일 뿐이다. 그리고 태그로 해석될 < 가 남았나: false.

왜: &를 나중에 바꾸면 이미 만든 &lt;가 &amp;lt;로 이중 변환된다. 한 번의 replace와 대응표로 처리하면 순서 문제가 사라진다. 겹치는 구간은 Math.max(start, last)로 뒤로 가지 않게 한다(위젯은 경계로 쪼개 겹침을 표현).

function findQuote(text, quote, from = 0, to = text.length) {
  const map = [];
  let compact = '';
  for (let i = from; i < to; i++) {
    if (/\s/.test(text[i])) continue;
    compact += text[i];
    map.push(i);
  }
  const q = quote.replace(/\s+/g, '');
  const k = q ? compact.indexOf(q) : -1;
  if (k < 0) return null;
  return { start: map[k], end: map[k + q.length - 1] + 1 };
}

import { chunk } from '/assets/js/core/chunker.js';

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const saved = await (await fetch('/assets/data/w11/answers.json')).json();

const chunks = new Map();
for (const d of corpus.documents)
  for (const c of chunk(d.text, saved.retrieval.chunk)) chunks.set(`${d.id}#${c.index}`, c.text);

const CITE = /\[(\d+(?:\s*,\s*\d+)*)\]/g;
const splitSentences = (t) => t.split(/(?<=[.!?])\s+/).filter(Boolean);
const parse = (t) => [...t.matchAll(CITE)].flatMap((m) => m[1].split(',').map(Number));
const REFUSAL = /찾을 수 없|알 수 없|내용이 없/;
const hasNumber = (src, n) => new RegExp(`(?<![\d.])${n.replace('.', '\.')}(?!\d)`).test(src);

function score(answer, sourceTexts) {
  let claims = 0, cited = 0, grounded = 0;
  for (const s of splitSentences(answer)) {
    if (REFUSAL.test(s)) continue;
    claims++;
    const valid = parse(s).filter((n) => n >= 1 && n <= sourceTexts.length);
    if (valid.length === 0) continue;
    cited++;
    const evidence = valid.map((n) => sourceTexts[n - 1]).join('\n');
    const numbers = s.replace(CITE, '').match(/\d+(?:\.\d+)?/g) ?? [];
    if (numbers.every((n) => hasNumber(evidence, n))) grounded++;
  }
  return { claims, cited, coverage: claims ? cited / claims : null, grounded: claims ? grounded / claims : null };
}

const rows = saved.items.map((it) => ({ id: it.id, kind: it.kind, ...score(it.answer, it.sources.map((id) => chunks.get(id))) }));
console.table(rows);
const scored = rows.filter((r) => r.coverage !== null);
const avg = (k) => scored.reduce((a, r) => a + r[k], 0) / scored.length;
console.log(`매크로 평균 (${scored.length}문항) coverage=${avg('coverage').toFixed(3)} grounded=${avg('grounded').toFixed(3)}`);

토론: bad-dorm(기숙사 거짓)은 두 지표가 모두 1이다. 숫자가 없는 거짓은 숫자 검사로 못 잡는다. bad-q01의 “[2] 장비 고장”도 숫자가 없어 grounded로 잡히지 않는다. 지표는 필요조건일 뿐이다 → 핵심어 검사(위젯)와 LLM 판정(Faithfulness)을 겹쳐 쓴다.
