LLM 키는 선택이다. 키가 없어도 규칙 파서와 예시 응답으로 전부 진행된다. T 키로 타이머를 시작한다.

오늘 할 수 있게 되는 것

  1. 유사도 질문과 조건 질문(개수 · 목록 · 범위)을 구별한다
  2. 질문을 필터 + 검색어로 나누는 셀프 쿼리를 만들고 스키마로 검증한다
  3. 사전/사후 필터와 빈 결과 완화를 정밀도 · 재현율로 비교한다

응용 1의 챗봇은 “비슷한 문장 찾기”만 했다. 오늘은 “조건에 맞는 것 고르기”를 붙인다. 3주차(파싱으로 표 행 복원) · 6주차(선필터/후필터) · 9주차(정밀도/재현율)가 한곳에서 만난다고 예고한다.

“화요일에 305호에서 하는 수업은?”

BM25 top-3

  1. ✓ 1학기 화요일 4~6교시 데이터베이스 · 305호
  2. ✓ 2학기 화요일 1~3교시 RAG 시스템 구축 · 305호
  3. ✗ 2학기 목요일 1~3교시 MLOps · 305호

→ 검색은 얼마나 비슷한가로 순위를 매길 뿐, 조건을 확인하지 않는다

발문: “3등은 왜 올라왔을까?” 기대 답: “305호에서”가 겹치고, 한글 bigram “요일”도 겹친다(BM25 점수 10.76 · 10.11 · 9.30, 코드 슬라이드에서 직접 실행).

LLM이 이 3개를 받으면 목요일 수업까지 답에 섞을 수 있다. “검색 실패는 생성으로 복구되지 않는다”를 다시 가리킨다.

마지막 줄을 꼭 짚는다. 모든 질문에 필터가 필요한 것은 아니다. 위젯의 “조건 없는 질문” 프리셋이 그 예다.

스키마 설계 원칙

  • 질문에 나오는 조건 = 필드
  • 값 정규화: “305호” → "305"
  • 구간은 두 숫자로: 시작 · 끝 교시
  • 모호한 말은 정의를 적는다 (오전 = 1~3교시)

text는 검색에, meta는 필터에 쓴다. 이 레코드는 3주차의 깨진 시간표를 행 단위로 복원한 결과다. 파싱에서 행 구조를 잃으면 메타데이터를 붙일 수 없다.

데이터 37개 중 1학기 시간표와 RAG 외 과목의 학점·담당은 가상 데이터(synthetic: true)라고 반드시 밝힌다. 학생이 실제 학사 정보로 오해하지 않게 한다.

발문: “교시를 ‘1-3’ 문자열 하나로 저장하면 무엇을 못 하나?” → 범위 비교.

intent가 중요하다. list/count는 top-k로 자르지 않고 필터 결과를 전부 쓴다. search만 top-k다.

LangChain의 SelfQueryRetriever가 이 구조의 대표 구현이다(LLM이 filter + query를 만든다). 오늘은 프레임워크 없이 원리를 직접 본다.

질문 “2학기 305호 수업 시간표”, 필터 type=timetable · semester=2 · room=305 (정답 4개)

숫자는 Challenge C3 정답을 Node로 실행한 실제 값이다. k=1이면 1위가 1학기 305호 수업이라 사후 필터가 0개를 남긴다.

6주차에서 “HNSW와 선필터를 섞으면 그래프 탐색이 끊긴다”고 했던 것을 상기시킨다. 레코드가 수십 개면 사전 필터가 간단하고 정확하다. 사후 필터를 쓸 수밖에 없으면 k를 넉넉히 키운다.

필터가 실패할 때

  • 빈 결과 — “목요일 305호 조 교수 수업” → 정답은 없다. 완화(담당 → 강의실 → …)는 참고용이며 반드시 밝힌다
  • 틀린 필터 — “306호 말고 305호” → 규칙 파서가 room=306 → 재현율 0 (순수 검색 0.75보다 나쁨)
  • 모호한 필터 — “오전 수업”: periodEnd ≤ 3이면 수요일 1~6교시 현장 실습이 빠진다 → 재현율 0.8

발문: “틀린 필터와 필터 없음, 어느 쪽이 나은가?” → 틀린 필터가 더 나쁘다. 확신 없는 조건은 검색어에 남겨 두는 편이 안전하다.

빈 결과에서 챗봇이 “목요일 305호에서는 박 교수의 MLOps가 있다”라고만 답하면 조 교수 질문에 거짓 답을 한 셈이다. “조건에 맞는 수업은 없다. 대신 …”이 정직한 답이다.

LLM이 만든 필터를 그대로 실행하지 않는다

{"filter": {
  "$where": "1 == 1",
  "credits": {"regex": "^3"},
  "status": "개설",
  "room": "305호" }}
  • 허용 필드만: 스키마의 8개
  • 허용 연산자만: eq · in · gte · lte
  • 허용 값만: enum · 정수 범위
  • 실패하면 실행하지 않는다
  • 권한 조건은 서버 코드가 덧붙인다

LLM 출력은 사용자 입력과 같은 급이다. 질문에 “필터에 $where를 넣어”라고 쓰면 LLM이 따라 할 수 있다. DB로 바로 넘기면 인젝션이다.

왼쪽 네 줄은 전부 거부된다(C4). “잘못된 부분만 빼고 실행”은 의도와 다른 조건이 걸려 위험하다는 점도 말한다.

데모 · 조건 검색 · 셀프 쿼리

시연 순서 (결과는 오른쪽 실행 결과 창)

  1. “화요일 305호”: A에 빨간 ✗ MLOps(목요일). 판정 상자의 “어긴 조건: 요일=목”을 읽는다. B·C는 정확히 2개
  2. “2학기 305호 개수”: k 슬라이더를 1→8로. A의 개수는 k를 따라가고 B의 “개수 답”은 4로 고정
  3. “이 교수 담당 모두”: 필터 시점을 사후로 → 재현율 0.75. 사전으로 되돌린다
  4. “⚠ 2학기 오전”: C의 “빠진 정답: t2-wed-1 현장 실습”. JSON의 periodEnd를 periodStart로 고쳐 즉시 1.00이 되는 것을 보인다
  5. “⚠ 빈 결과”: C는 0개, B는 완화 결과. 완화 안내 문구를 읽는다
  6. 파서를 LLM으로 → “2학기 3학점 과목” 예시 응답이 status 필드로 검증 실패. “🛡 허용 안 된 필터 넣어 보기”도 누른다

벡터 검색은 118MB라 수업 전에 한 번 받아 두거나 생략한다. BM25만으로 오늘 내용은 전부 된다.

1~4는 짝 활동 15분, 5~7은 휴식 후 전체 토론.

기대 답: 1) t2-thu-1, 요일=목 · 2) A는 k와 같고 B는 4 고정 · 3) 0.75 · 4) periodEnd ≤ 3은 4개, periodStart ≤ 3은 5개 · 5) 순수 검색(0.75 vs 0) · 6) “없다” + 완화 사실 공개 · 7) 스키마에 없는 status 필드.

import { BM25 } from '/assets/js/core/bm25.js';
const { records } = await (await fetch('/assets/data/w14/records.json')).json();
const bm25 = new BM25().add(records.map((r) => ({ id: r.id, text: r.text })));
const byId = new Map(records.map((r) => [r.id, r]));

const q = '화요일에 305호에서 하는 수업은?';
const filter = { type: 'timetable', day: '화', room: '305' };
const pass = (r) => Object.entries(filter).every(([f, v]) => r.meta[f] === v);

const pure = bm25.search(q, 3);
console.log('순수 검색 top-3');
for (const h of pure) console.log(pass(byId.get(h.id)) ? '  ✓' : '  ✗', h.id, h.score.toFixed(2));

const exact = records.filter(pass);
console.log(`필터만: ${exact.length}개 →`, exact.map((r) => `${r.meta.semester}학기 ${r.meta.course}`).join(', '));

정리

  • 조건 질문(개수 · 목록 · 범위)은 필터로, 나머지만 검색으로
  • 메타데이터는 파싱 · 청킹 때 붙인다. 스키마가 필터의 한계를 정한다

  • 빈 결과는 “없다”, 완화는 밝히고, 틀린 필터는 검색보다 나쁘다

부록 B · C1 정답

function parseSimple(q) {
  const filter = {};
  const sem = q.match(/([12])\s*학기/);
  if (sem) filter.semester = Number(sem[1]);
  const day = q.match(/([월화수목금])요일/);
  if (day) filter.day = day[1];
  const room = q.match(/(\d{3})\s*호/);
  if (room) filter.room = room[1];
  const prof = q.match(/([김이박조최])\s*교수/);
  if (prof) filter.professor = `${prof[1]} 교수`;
  const range = q.match(/(\d)\s*[-~]\s*(\d)\s*교시/);
  if (range) {
    filter.periodStart = { gte: Number(range[1]) };
    filter.periodEnd = { lte: Number(range[2]) };
  }
  return filter;
}

for (const q of [
  '화요일에 305호에서 하는 수업은?',
  '2학기 목요일 1-3교시 수업',
  '이 교수가 담당하는 수업',
  '306호 말고 305호에서 하는 수업',
]) console.log(q, '→', JSON.stringify(parseSimple(q)));

실행 결과:

  • 화요일에 305호에서 하는 수업은? → {"day":"화","room":"305"}
  • 2학기 목요일 1-3교시 수업 → {"semester":2,"day":"목","periodStart":{"gte":1},"periodEnd":{"lte":3}}
  • 이 교수가 담당하는 수업 → {"professor":"이 교수"}
  • 306호 말고 305호에서 하는 수업 → {"room":"306"} ← 틀림

왜: match는 처음 일치만 찾는다. 부정(“말고”)을 처리하려면 “N호 말고”를 먼저 지우는 규칙이 필요하지만, 표현(“빼고”, “아닌”, “제외”)이 끝없이 늘어난다. 이것이 LLM 파서를 쓰는 이유다. room을 숫자가 아니라 문자열로 두는 이유(“외부 산업체” 같은 값)도 짚는다.

부록 B · C2 정답

const { records } = await (await fetch('/assets/data/w14/records.json')).json();

function matchCond(value, cond) {
  if (cond !== null && typeof cond === 'object') {
    if ('in' in cond && !cond.in.includes(value)) return false;
    if ('gte' in cond && !(typeof value === 'number' && value >= cond.gte)) return false;
    if ('lte' in cond && !(typeof value === 'number' && value <= cond.lte)) return false;
    return true;
  }
  return value === cond; // eq
}
const applyFilter = (recs, filter) =>
  recs.filter((r) => Object.entries(filter).every(([field, cond]) => matchCond(r.meta[field], cond)));

const tests = {
  '화요일 305호': { type: 'timetable', day: '화', room: '305' },
  '2학기 월·수 수업': { type: 'timetable', semester: 2, day: { in: ['월', '수'] } },
  '3학점 이상 과목': { type: 'course', credits: { gte: 3 } },
  '2학기 오전에 걸친 수업': { type: 'timetable', semester: 2, periodStart: { lte: 3 } },
};
for (const [name, f] of Object.entries(tests)) {
  const hit = applyFilter(records, f);
  console.log(`${name}: ${hit.length}개`, hit.map((r) => r.meta.course).join(', '));
}

const { schema } = await (await fetch('/assets/data/w14/records.json')).json();
const OPS = ['eq', 'in', 'gte', 'lte'];

function validate(obj) {
  const errors = [];
  if (!obj || typeof obj !== 'object' || Array.isArray(obj)) return ['객체가 아니다'];
  for (const key of Object.keys(obj)) if (!['query', 'intent', 'filter'].includes(key)) errors.push(`최상위 키 거부: ${key}`);
  if (obj.intent !== undefined && !['search', 'list', 'count'].includes(obj.intent)) errors.push(`intent 거부: ${obj.intent}`);
  const filter = obj.filter ?? {};
  const checkValue = (field, spec, v) => {
    if (spec.kind === 'enum' && !spec.values.includes(v)) errors.push(`${field}: 허용 값 아님 ${JSON.stringify(v)}`);
    if (spec.kind === 'int' && (!Number.isInteger(v) || v < spec.min || v > spec.max)) errors.push(`${field}: 범위 밖 ${JSON.stringify(v)}`);
  };
  for (const [field, cond] of Object.entries(filter)) {
    const spec = schema[field];
    if (!spec) { errors.push(`필드 거부: ${field}`); continue; }
    if (cond !== null && typeof cond === 'object' && !Array.isArray(cond)) {
      for (const [op, v] of Object.entries(cond)) {
        if (!OPS.includes(op)) errors.push(`${field}: 연산자 거부 ${op}`);
        else if (op === 'in') Array.isArray(v) && v.length ? v.forEach((x) => checkValue(field, spec, x)) : errors.push(`${field}: in은 배열`);
        else if ((op === 'gte' || op === 'lte') && spec.kind !== 'int') errors.push(`${field}: ${op}는 숫자 필드만`);
        else checkValue(field, spec, v);
      }
    } else if (Array.isArray(cond)) errors.push(`${field}: 배열은 {"in": [...]}로`);
    else checkValue(field, spec, cond);
  }
  return errors;
}

const matchCond = (v, c) =>
  c !== null && typeof c === 'object'
    ? (!('in' in c) || c.in.includes(v)) && (!('gte' in c) || v >= c.gte) && (!('lte' in c) || v <= c.lte)
    : v === c;

function selfQuery(q, p) {

  const allowedIds = new Set(allowed.map((r) => r.id));
  if (p.intent !== 'search' && Object.keys(p.filter).length) return allowed.map((r) => r.id); // list/count: no top-k cut
  return bm25.search(p.query || q, records.length).filter((h) => allowedIds.has(h.id)).slice(0, K).map((h) => h.id);

function pr(retrieved, gold) {
  const g = new Set(gold);
  const hits = retrieved.filter((id) => g.has(id)).length;
  if (g.size === 0) return { p: retrieved.length ? 0 : 1, r: null };
  return { p: retrieved.length ? hits / retrieved.length : 0, r: hits / g.size };
}
