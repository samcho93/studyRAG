2왜 필요한가

7주차의 최소 RAG는 벡터 검색 하나로 근거를 찾았다. 장학금 안내 문서 끝에는 “문의 : 학생지원팀 (내선 2l4)”라는 줄이 있다. 누군가 내선 번호 2l4를 검색창에 그대로 넣으면 어떻게 될까.

벡터 검색의 실패: 뜻이 없는 토큰

multilingual-e5-small로 37개 청크를 검색하면 2l4가 들어 있는 청크는 4위다. 1위는 “Copyright © 한국폴리텍대학…”으로 끝나는 FAQ 페이지의 푸터다. 임베딩 모델에게 2l4는 의미가 없는 글자 조각이라 어느 청크와도 특별히 가깝지 않다.

그렇다면 글자를 그대로 맞추는 키워드 검색으로 바꾸면 될까. 이번에는 반대 방향에서 실패한다.

키워드 검색의 실패: 같은 뜻, 다른 단어

“모델이 없는 사실을 지어내는 현상”을 BM25로 검색하면 정답 청크(“…그럴듯한 거짓을 만들어 낸다. 이를 환각이라 한다”)는 7위다. 질문의 “지어내는”, “현상”이 문서에는 한 번도 나오지 않는다. 같은 질문을 벡터 검색은 1위로 찾는다.

두 검색기의 사각지대는 겹치지 않는다. 그래서 둘 다 돌리고 결과를 합친다. 이것이 하이브리드 검색(hybrid search)이다. 문제는 “어떻게 합치는가”다. BM25 점수는 0에서 40 가까이까지 나오고 코사인 유사도는 대부분 0.8~0.9 사이에 몰려 있어서 그대로 더하면 BM25가 결과를 독차지한다.

3개념

하이브리드 검색의 흐름

BM25: 드문 단어가 여러 번, 짧은 청크에

BM25는 질문의 토큰이 청크에 몇 번, 얼마나 드물게 나오는지로 점수를 매기는 키워드 검색 방식이다. 직관은 세 가지다.

요소직관이 문서셋의 예
TF (단어 빈도)질문 토큰이 청크에 많이 나올수록 관련이 높다. 단, 한없이 커지지 않고 포화된다“청킹”이 세 번 나온 청크가 한 번 나온 청크보다 높지만 세 배는 아니다
IDF (역문서 빈도)여러 청크에 흔한 토큰은 변별력이 없다. 드문 토큰일수록 가치가 크다“검색”은 37개 중 17개 청크에 있어 IDF 0.78, 2l4는 1개에만 있어 IDF 3.23
길이 정규화긴 청크는 우연히 단어가 걸릴 확률이 높으므로 점수를 깎는다토큰 41개인 장학금 청크는 평균(74.6개)보다 짧아 이득을 본다

직관을 식으로 쓰면 다음과 같다. f는 청크 안에서 토큰의 빈도, |d|는 청크의 토큰 수, avgdl은 평균 청크 길이, N은 청크 수, n은 그 토큰이 들어 있는 청크 수다. core/bm25.js는 k1 = 1.5, b = 0.75를 쓴다.

BM25(q, d) = Σ  IDF(t) × f·(k1 + 1) / ( f + k1·(1 − b + b·|d|/avgdl) )
            t∈q
IDF(t)     = ln( 1 + (N − n + 0.5) / (n + 0.5) )

예) 질문 "2l4", 장학금 청크 #2:  N=37, n=1, f=1, |d|=41, avgdl=74.6
    IDF = ln(1 + 36.5/1.5) = 3.232
    TF  = 2.5 / (1 + 1.5·(0.25 + 0.75·41/74.6)) = 1.254
    점수 = 3.232 × 1.254 ≈ 4.05

한국어는 왜 바이그램을 더하나

영어는 공백으로 단어가 나뉘지만 한국어는 조사와 어미가 붙는다. 문서에는 “305호와”, 질문에는 “305호”라고 쓰면 공백 기준 토큰은 서로 다른 문자열이라 한 번도 일치하지 않는다. core/bm25.js는 한글이 들어간 어절에 대해 두 글자씩 자른 바이그램(bigram)을 함께 색인한다.

tokenize("305호")        → 305호 · 30 · 05 · 5호
tokenize("305호와 306호를") → 305호와 · 30 · 05 · 5호 · 호와 · 306호를 · 30 · 06 · 6호 · 호를
                                           ↑ "30", "05", "5호"가 겹쳐서 일치한다

대가도 있다. 바이그램은 “인덱스의” 속 “인덱”처럼 관련 없는 청크에서도 걸리는 조각을 늘려 순위를 흐린다. 또 이 토크나이저는 “MRR은”처럼 영문과 한글이 붙은 어절을 통째로 두 글자씩 자르므로 mrr이라는 토큰이 생기지 않는다. 그래서 “MRR”로 검색하면 BM25는 평가 청크를 찾지 못한다. 실무에서는 형태소 분석기(예: Elasticsearch의 Nori)로 조사를 떼어 낸다. Challenge C3에서 바이그램이 얻는 것과 잃는 것을 직접 잰다.

벡터 검색의 강점과 약점

잘하는 것못하는 것
벡터바꿔 말한 질문(“졸업하려면 출석을 얼마나…” → “수료 요건은 출석률 80% 이상”)코드·번호·고유명사(2l4, 3분위), 뜻이 비슷하지만 숫자만 다른 문장, 짧고 내용 없는 청크가 여러 질문에서 상위로 떠오르는 현상
BM25정확히 같은 토큰, 드문 용어, 오타까지 그대로 쓴 OCR 문자열동의어·바꿔 말하기, 토크나이저가 쪼개지 못한 어절

점수 스케일이 달라서 순위를 합친다: RRF

질문 “실습실에서 GPU 서버를…”의 BM25 상위 10개 점수는 36.8에서 3.1까지 퍼져 있다. 같은 질문의 코사인 유사도는 0.90에서 0.81 사이에 몰려 있다. 두 값을 더하면 코사인 차이는 반올림 오차 수준이 된다. RRF(Reciprocal Rank Fusion)는 점수를 버리고 순위만 쓴다.

RRF(d) = Σ  1 / (k + r_i(d))        r_i(d): i번째 목록에서 d의 순위 (없으면 그 항은 0)
         i

예) "모델이 없는 사실을 지어내는 현상", k = 60
    RAG란 #0   : BM25 7위, 벡터 1위 → 1/67 + 1/61 = 0.0313
    임베딩 #2   : BM25 1위, 벡터 7위 → 1/61 + 1/67 = 0.0313   ← 완전히 같은 점수

k는 1위와 아래 순위의 차이를 조절한다. k = 1이면 1위가 1/2, 2위가 1/3으로 1위의 몫이 크다. k = 60이면 1/61과 1/62로 거의 같아져서 “한쪽 목록의 1위”보다 “양쪽 목록에 모두 있는 청크”가 이긴다. 원 논문(Cormack 외, 2009)이 실험으로 고른 60이 사실상 기본값이다. 순위만 쓰므로 위의 예처럼 동점이 흔하다는 점도 기억한다.

가중 융합: 정규화한 점수를 α로 섞는다

점수를 살리고 싶다면 각 목록을 min-max로 0~1에 맞춘 뒤 가중합한다.

norm(s) = (s − min) / (max − min)
score(d) = α · norm(코사인) + (1 − α) · norm(BM25)      α = 0 → BM25만, α = 1 → 벡터만

“BM25 1위가 압도적인가, 근소한가”라는 정보가 남는 것이 장점이다. 반대로 min-max는 목록의 꼴찌를 무조건 0으로 만들고, 결과가 하나뿐인 목록은 그 하나를 1로 만든다. α는 문서셋마다 다르므로 9주차 평가 데이터로 골라야 한다.

리랭킹: 비싼 모델은 후보에게만

리랭킹(reranking)은 1차 검색이 뽑은 후보를 더 정교한 모델로 다시 줄 세우는 단계다. 지금까지의 벡터 검색은 질문과 청크를 따로 임베딩하는 바이 인코더(bi-encoder)다. 청크 벡터를 미리 계산해 둘 수 있어 빠르지만, 질문과 청크의 단어가 서로를 직접 보지 못한다. 크로스 인코더(cross-encoder)는 “질문 + 청크”를 한 입력으로 넣어 관련도 하나를 출력한다. 두 텍스트의 토큰이 어텐션으로 서로를 보므로 정확하다.

바이 인코더 (1차 검색)크로스 인코더 (리랭커)
입력질문, 청크를 각각질문과 청크를 한꺼번에
미리 계산청크 벡터를 색인 때 한 번불가능 — 질문이 올 때마다 계산
질문 하나의 비용질문 임베딩 1번 + 벡터 비교후보 수만큼 모델 추론 (후보 50개면 50번)

그래서 크로스 인코더는 전체 청크가 아니라 하이브리드 검색이 뽑은 상위 20~100개에만 적용한다. 리랭커는 1차 검색이 후보에 넣지 못한 청크를 되살릴 수 없다는 점에 주의한다. 이 사이트는 브라우저에서 돌릴 크로스 인코더를 쓰지 않으므로, 실습 위젯의 리랭커는 원리만 흉내 낸 장난감이다(키워드 커버리지 50% + 문서 제목을 붙인 청크와의 코사인 50%).

4실습

아래 위젯은 문서셋 12개를 재귀 분할(200자)로 자른 37개 청크를 BM25와 벡터로 동시에 검색한다. BM25 결과는 바로 나오고, 벡터 결과는 임베딩 모델(약 118MB, 최초 1회 다운로드)이 준비되면 채워진다. 초록 테두리와 ✓는 정답 근거가 든 청크다. 항목을 누르면 청크 원문과 질문 토큰이 일치한 부분이 아래에 표시된다. 결과는 오른쪽 실행 결과 창에 나온다.

관찰 질문

  1. 처음 화면(① 바꿔 말하기)에서 모델이 준비되기 전, BM25 1위 청크를 눌러 노란 표시를 본다. BM25는 질문의 어떤 조각 때문에 이 청크를 1위로 골랐나?
  2. 모델이 준비되면 하이브리드 열에 RRF 점수가 0.0313으로 같은 청크가 여럿 보인다. 두 청크의 B·V 순위를 읽고 1/(60+r) 계산으로 왜 같은지 설명한다.
  3. ② 코드 토큰 2l4를 누른다. 벡터 1위는 어떤 청크인가? 짧고 내용 없는 청크가 여러 질문에서 벡터 상위에 오르는 이유를 추측한다.
  4. ④ 표 깨짐을 누르고 k와 α를 끝까지 움직여 본다. 근거가 3위 안에 들어오는 설정이 있는가? 이 실패는 어느 주차의 단계에서 고쳐야 하나?
  5. 질문 목록에서 x10 “글을 자를 때 겹치게 하면 손해는?”을 고른다. RRF(k=60)와 가중합(α=0.5)에서 근거 순위를 비교한다. 어느 쪽이 나은지, BM25 열의 결과와 연결해 설명한다.
  6. 장난감 리랭커를 켜고 여러 질문을 바꿔 본다. ▲로 좋아진 질문과 ▼로 나빠진 질문을 하나씩 찾는다. 리랭커가 항상 좋아지게 만들려면 어떤 조건이 필요할까?

6정리 & 다음 주 예고

  • BM25는 글자가 같아야 찾고, 벡터 검색은 뜻이 가까워야 찾는다. 코드·번호에는 BM25, 바꿔 말한 질문에는 벡터가 강하다.
  • BM25 점수와 코사인 유사도는 스케일이 달라 그대로 더할 수 없다. RRF는 순위만 써서 이 문제를 피하고, k = 60이 기본값이다.
  • 가중 융합은 min-max로 점수를 맞춘 뒤 α로 섞는다. α는 문서셋마다 측정해서 고른다.
  • 크로스 인코더 리랭커는 정확하지만 후보마다 추론하므로 1차 검색의 상위 후보에만 쓴다. 약한 리랭커는 오히려 순위를 망친다.
  • 근거 청크가 망가져 있으면(표 깨짐) 어떤 융합도 고치지 못한다.
