BM25는 결과가 딱 하나 — 바로 그 청크

발문: “7주차에 만든 RAG에 이 질문을 넣으면 LLM은 무엇을 받게 되나?” → 푸터와 시간표를 받고 내선 번호를 모른다고 하거나 지어낸다.

2l4는 OCR이 214를 잘못 읽은 문자열이다(3주차 문서). 사용자는 문서에 적힌 그대로 복사해 검색하는 경우가 많다는 점을 짚는다. 수치는 사전 계산 데이터(assets/data/w08/hybrid.json) 기준이며 브라우저에서 순위가 한 칸 정도 다를 수 있다.

반대로, BM25가 실패하는 질문

“모델이 없는 사실을 지어내는 현상”

BM25 → 7위

문서: “…그럴듯한 거짓을 만들어 낸다. 이를 환각이라 한다”

“지어내는”, “현상”이 문서에 없다

두 실패를 칠판 양쪽에 적는다: 왼쪽 “글자는 같은데 뜻이 없음(코드·번호)”, 오른쪽 “뜻은 같은데 글자가 다름(바꿔 말하기)”. 오늘 내내 이 두 칸을 가리킨다.

발문: “우리 학과 문서에서 코드처럼 생긴 검색어는 또 뭐가 있을까?” (강의실 305호, 과목 코드, 학번, 에러 코드 등)

BM25: 드문 단어가 여러 번, 짧은 청크에

TF많이 나올수록 ↑, 하지만 포화된다 (k1 = 1.5)
IDF“검색” 17/37개 청크 → 0.78 · “2l4” 1/37 → 3.23
길이긴 청크는 깎는다 (b = 0.75, 평균 74.6 토큰)
 
IDF = ln(1 + (37 − 1 + 0.5)/(1 + 0.5)) = 3.232
TF  = 2.5 / (1 + 1.5·(0.25 + 0.75·41/74.6)) = 1.254
BM25("2l4", 장학금#2) = 3.232 × 1.254 ≈ 4.05

식은 보여 주기만 하고, 세 요소의 직관을 먼저 말로 확인한다. “흔한 단어가 많이 나오는 긴 문서”가 불리하다는 문장으로 요약한다.

위젯 BM25 열의 4.05와 이 계산이 정확히 일치함을 데모 때 보여 준다. TF 포화: f가 1→2→3이면 TF 부분이 1.25→1.67→1.88 정도로 늘어난다(같은 길이일 때)는 점을 말로 덧붙인다.

한국어는 왜 바이그램을 더하나

"305호"          → 305호 · 30 · 05 · 5호
"305호와 306호를" → 305호와 · 30 · 05 · 5호 · 호와 · 306호를 · …
  • 조사가 붙어 공백 토큰이 안 맞는다 → 두 글자 조각으로 부분 일치
  • 대가 1: “인덱스의” → “인덱” 같은 조각이 엉뚱한 청크에도 걸린다
  • 대가 2: “MRR은” → mrr은 · mr · rr · r은 — mrr이 없다

실무: 형태소 분석기(Nori, Mecab-ko)로 조사를 떼어 낸다

바이그램을 끄면 “305호”는 BM25로 아예 못 찾는다(x03). 반대로 “HNSW 인덱스의 단점은?”(q09)은 바이그램 때문에 4위로 밀리고, 끄면 1위다. C3에서 학생이 직접 확인한다.

“MRR”로 검색하면 BM25 결과가 0개다. core 토크나이저가 영문+한글이 붙은 어절을 나누지 않기 때문이다. 토론 D-3의 재료.

점수가 아니라 순위를 더한다: RRF

BM25 36.8 ~ 3.1  vs  코사인 0.90 ~ 0.81 → 그대로 더하면 BM25 독식

RRF(d) = Σ 1 / (k + rᵢ(d))        k = 60

RAG란 #0 : BM25 7위 · 벡터 1위 → 1/67 + 1/61 = 0.0313
임베딩 #2 : BM25 1위 · 벡터 7위 → 1/61 + 1/67 = 0.0313

순위만 쓰니 교정이 필요 없다. 대신 동점이 흔하다

발문: “점수 스케일이 다른 두 시험(100점 만점, 5점 만점)을 합쳐 1등을 뽑으려면?” → 석차를 쓰자는 답을 끌어낸다. 그게 RRF다.

위의 동점은 실제 위젯 첫 화면(① 바꿔 말하기)에서 그대로 보인다. 동점일 때 core rrf는 먼저 넣은 목록(BM25)의 항목을 앞에 둔다(안정 정렬).

k의 의미, 그리고 가중 융합

RRF의 k

A: BM25 1위만 · D: 양쪽 4위

k=1  : A 0.500 > D 0.400
k=60 : D 0.031 > A 0.016

k가 크면 “양쪽에 다 있는” 청크가 이긴다

가중합

α·norm(cos) + (1−α)·norm(BM25)

점수 차이 정보를 살린다

min-max는 꼴찌를 0으로 만든다 · α는 측정으로 고른다

왼쪽 예시는 C1의 목록 그대로다(bm25 = A B C D, vector = C E F D). k=1이면 A가 D보다 위, k=60이면 뒤집힌다.

C4 결과를 미리 살짝 흘린다: 이 문서셋 22문항에서는 가중합(α=0.5)이 hit@3 0.95로 RRF(0.86)보다 높았다. “RRF가 항상 정답은 아니다, 측정해서 고른다.”

리랭킹: 비싼 모델은 후보에게만

바이 인코더크로스 인코더
입력질문, 청크 따로질문 + 청크 한꺼번에
미리 계산청크 벡터 OX (질문마다)
비용임베딩 1번 + 내적후보 수 × 추론
정확도보통높음

하이브리드 상위 20~100개 → 크로스 인코더 → 상위 3~5개를 LLM에

리랭커는 후보에 없는 청크를 되살리지 못한다. 그래서 1차 검색의 재현율(recall)이 먼저다.

브라우저에서 돌릴 만한 크로스 인코더가 없어 위젯의 리랭커는 장난감이다: 0.5 × 키워드 커버리지 + 0.5 × “문서 제목: 청크” 임베딩과의 코사인(후보 안에서 min-max). 4주차 C5(제목 붙이기)와 연결된다. 실제 제품 예: bge-reranker 계열, Cohere Rerank.

부록 B · C1 정답

import { rrf } from '/assets/js/core/rerank.js';

const bm25 = ['A', 'B', 'C', 'D'];
const vector = ['C', 'E', 'F', 'D'];

function myRrf(lists, k = 60) {
  const scores = new Map();
  for (const list of lists) {
    list.forEach((id, i) => scores.set(id, (scores.get(id) ?? 0) + 1 / (k + i + 1)));
  }
  return [...scores].map(([id, score]) => ({ id, score })).sort((a, b) => b.score - a.score);
}

const mine = myRrf([bm25, vector]);
const core = rrf([bm25, vector].map((l) => l.map((id) => ({ id }))), { k: 60 });
console.table(mine.map((m, i) => ({
  id: m.id, mine: m.score.toFixed(5), core: core[i].score.toFixed(5),
  same: m.id === core[i].id && Math.abs(m.score - core[i].score) < 1e-12,
})));
for (const k of [1, 60]) console.log(`k=${k}:`, myRrf([bm25, vector], k).map((r) => `${r.id}(${r.score.toFixed(3)})`).join(' '));

기대 출력: C 0.03227 · D 0.03125 · A 0.01639 · B 0.01613 · E 0.01613 · F 0.01587, core와 모두 same = true. k=1: C 0.750, A 0.500, D 0.400 / k=60: C, D, A 순.

왜: 순위는 1부터 센다(i + 1). 0부터 세면 k=60에서는 차이가 작아 눈치채기 어렵지만 k=1에서 1위가 1/1이 되어 크게 틀린다. k가 작으면 한 목록의 1위가 독주하고, k가 크면 두 목록에 모두 나온 D가 A를 이긴다.

부록 B · C2 정답

import { weightedFusion } from '/assets/js/core/rerank.js';

const bm25 = [{ id: 'A', score: 12.4 }, { id: 'B', score: 7.9 }, { id: 'C', score: 2.1 }];
const vector = [{ id: 'C', score: 0.871 }, { id: 'D', score: 0.866 }, { id: 'A', score: 0.812 }];

// 1) raw sum: BM25 scores are ~10x larger, so they decide everything
const raw = new Map();
for (const r of [...bm25, ...vector]) raw.set(r.id, (raw.get(r.id) ?? 0) + r.score);
console.log('단순합:', [...raw].sort((a, b) => b[1] - a[1]).map(([id, s]) => `${id}(${s.toFixed(3)})`).join(' '));

// 2) min-max
function minMax(list) {
  const xs = list.map((r) => r.score);
  const lo = Math.min(...xs), hi = Math.max(...xs);
  return list.map((r) => ({ id: r.id, score: hi === lo ? 1 : (r.score - lo) / (hi - lo) }));
}

// 3) weighted fusion; a missing item contributes 0 from that list
function fuse(vec, kw, alpha) {
  const out = new Map();
  for (const r of minMax(vec)) out.set(r.id, alpha * r.score);
  for (const r of minMax(kw)) out.set(r.id, (out.get(r.id) ?? 0) + (1 - alpha) * r.score);
  return [...out].map(([id, score]) => ({ id, score })).sort((a, b) => b.score - a.score);
}

// 4) alpha sweep vs core
const rows = [0, 0.3, 0.5, 0.7, 1].map((alpha) => {
  const mine = fuse(vector, bm25, alpha);
  const core = weightedFusion(vector, bm25, { alpha });
  return {
    alpha,
    mine: mine.map((r) => `${r.id}:${r.score.toFixed(2)}`).join(' '),
    core: core.map((r) => `${r.id}:${r.score.toFixed(2)}`).join(' '),
    same: mine.every((r, i) => r.id === core[i].id && Math.abs(r.score - core[i].score) < 1e-9),
  };
});
console.table(rows);

왜: A의 코사인 0.812는 벡터 목록의 꼴찌라서 min-max 뒤 0이 된다. 정규화는 목록 안에서의 상대 위치만 남긴다. 결과가 한 개뿐인 목록은 그 하나가 1이 되므로(“2l4”의 BM25) 과대평가될 수 있다는 점도 짚는다.

  chunks.filter((c) => it.evidence.some((e) => e.doc === c.doc && c.text.includes(e.quote))).map((c) => c.id);

const noBi = new BM25({ tokenizer: (t) => tokenize(t, { bigrams: false }) }).add(chunks);
const ids = (index, it) => index.search(it.question, 10).map((r) => r.id);

function score(index, items, k = 3) {
  let hit = 0, mrr = 0;
  for (const it of items) {
    hit += hitAtK(ids(index, it), relevant(it), k);
    mrr += reciprocalRank(ids(index, it), relevant(it));
  }
  return { hit: `${hit}/${items.length}`, mrr: +(mrr / items.length).toFixed(3) };
}

  return { set: name, bigram_hit3: a.hit, bigram_mrr: a.mrr, plain_hit3: b.hit, plain_mrr: b.mrr };
}));

const rank = (index, it) => ids(index, it).findIndex((id) => relevant(it).includes(id)) + 1 || '-';
console.table([...golden.items, ...data.extra]
  .map((it) => ({ id: it.id, q: it.question, bigram: rank(withBi, it), plain: rank(noBi, it) }))
  .filter((r) => r.bigram !== r.plain));

import { chunk } from '/assets/js/core/chunker.js';
import { BM25, tokenize } from '/assets/js/core/bm25.js';
import { rrf, rerank } from '/assets/js/core/rerank.js';
import { reciprocalRank } from '/assets/js/core/metrics.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const golden = await (await fetch('/assets/data/golden/golden.json')).json();
const data = await (await fetch('/assets/data/w08/hybrid.json')).json();
const chunks = corpus.documents.flatMap((d) =>
  chunk(d.text, data.chunking).map((c) => ({ id: `${d.id}#${c.index}`, doc: d.id, text: c.text.trim() })));
const byId = new Map(chunks.map((c) => [c.id, c]));
const relevant = (it) =>
  chunks.filter((c) => it.evidence.some((e) => e.doc === c.doc && c.text.includes(e.quote))).map((c) => c.id);
const bm25 = new BM25().add(chunks);

function coverage(query, text) {
  const q = [...new Set(tokenize(query))];
  const t = new Set(tokenize(text));
  return q.length ? q.filter((x) => t.has(x)).length / q.length : 0;
}
const cov = (q, c) => coverage(q, byId.get(c.id).text);

const items = [...golden.items, ...data.extra];
const sum = { before: 0, coverOnly: 0, mixed: 0 };
const changed = [];
for (const it of items) {
  const cands = rrf([bm25.search(it.question, 10), data.vector[it.id]], { k: 60, topK: 10 })
    .map((c, i) => ({ ...c, prior: 1 - i / 10 }));
  const lists = {
    before: cands,
    coverOnly: await rerank(it.question, cands, cov, { topK: 10 }),
    mixed: await rerank(it.question, cands, (q, c) => 0.5 * cov(q, c) + 0.5 * c.prior, { topK: 10 }),
  };
  const rr = Object.fromEntries(Object.entries(lists).map(([k, l]) => [k, reciprocalRank(l.map((r) => r.id), relevant(it))]));
  for (const k in sum) sum[k] += rr[k];
  if (rr.coverOnly !== rr.before || rr.mixed !== rr.before) changed.push({ id: it.id, ...rr });
}
console.table(changed.map((r) => ({ ...r, before: 1 / r.before, coverOnly: 1 / r.coverOnly, mixed: 1 / r.mixed })));
console.log('MRR', Object.fromEntries(Object.entries(sum).map(([k, v]) => [k, +(v / items.length).toFixed(3)])));
