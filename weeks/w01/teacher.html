첫 시간이므로 사이트를 python -m http.server로 여는 방법과 오른쪽 실행 결과 창 위치를 먼저 보여 준다. T 키로 타이머를 시작한다.

오늘 할 수 있게 되는 것

  1. 토큰 수 차이를 비용과 컨텍스트 창 사용률로 환산한다
  2. 환각이 왜 생기는지, 근거 없는 답을 왜 검증할 수 없는지 설명한다
  3. 근거 기반 프롬프트를 만들고, 답이 골든 정답을 포함하는지 판정하는 코드를 쓴다

3번의 groundedPrompt는 7주차 최소 RAG에서, 골든 사실 판정은 9주차 평가에서 다시 쓴다고 미리 말한다. 오늘 코드가 12주 동안 이어진다는 감각을 준다.

GPU 서버, 한 사람이 최대 몇 시간?

“보통 1회 4시간 정도로 제한한다.”

→ 우리 규정: 최대 12시간 (실습실 이용 규정)

LLM은 이 문서를 본 적이 없다. 그런데도 자신 있게 답했다

발문: 먼저 학생들에게 “몇 시간일 것 같나?”를 묻고 손을 들게 한다. 대부분 4~8시간을 고른다. LLM도 똑같이 “일반적인 값”을 고른다는 점을 연결한다.

이어서 “LLM이 맞혔다면 믿을 수 있었을까?”를 묻는다. 기대 답: 출처가 없어 확인할 수 없다 → 오늘의 핵심.

LLM은 다음 토큰을 예측한다

입력: 토큰 열 → 출력: 다음 토큰의 확률

  • 학습 데이터에 “대학 실습실 일반”은 많다
  • “우리 학과 규정”은 없다
  • 그래도 무언가는 반드시 출력한다
후보확률(예시)
4시간높음
8시간중간
12시간낮음

확률 값은 설명용이다. 실제 분포는 모델마다 다르다고 짚는다.

“모르는 것은 정상, 모를 때 지어내는 것이 문제”를 칠판에 적는다. 환각(hallucination)이라는 용어는 여기서 처음 준다.

LLM은 글자가 아니라 토큰을 읽는다

한글 음절 = UTF-8 3바이트 · 영어 중심 어휘는 이 바이트를 거의 합치지 못한다

숫자는 브라우저에서 Transformers.js 토크나이저(Xenova/gpt2, Xenova/gpt-4o)로 실제로 센 값이다.

발문: “글자 수는 한국어가 절반인데 왜 토큰은 4배인가?” → 다음 슬라이드의 창·비용으로 연결한다.

토큰 = 들어가는 양 = 내는 돈

창 사용률 = 입력 토큰 / 창 크기
입력 비용 = 입력 토큰 × 단가 / 1,000,000
  • 코퍼스 12문서: GPT-2 8,848토큰 → 8,192 창의 108% (넘침)
  • 같은 문서 GPT-4o: 2,660토큰 → 8,192 창의 32%
  • 문서 5,000개면? 약 110만 토큰 → 128K 창의 866%

“그럼 문서를 다 넣으면 되지 않나?”라는 질문이 반드시 나온다. 이 슬라이드가 답이다: 창에 안 들어가고, 들어가도 매번 돈을 낸다.

5,000개 계산은 Challenge C2의 마지막 문항이다(문서당 평균 221.7토큰 × 5,000 = 1,108,333토큰).

데모 · 토큰 카운터

시연 순서 (결과는 오른쪽 실행 결과 창에 실시간으로 나온다)

  1. 처음 화면: GPU 규정 문장. 표에서 GPT-2 한국어 161 vs 영어 35를 짚는다. 설명 카드의 배수 4.6배
  2. 토큰 조각을 GPT-2로: 점선 상자와 숫자 3 → “한 글자가 토큰 3개”
  3. GPT-4o로 바꾸면 “ 서버”, “시간”이 토큰 하나
  4. “코퍼스 전체 12문서” 프리셋 → 빨간 판정 “컨텍스트 창 초과”. 창을 1,024 / 128,000으로 바꿔 본다

토크나이저는 약 12MB다. 수업 전에 교탁 PC에서 한 번 열어 캐시해 둔다.

환각: 그럴듯한 거짓

모를 때 “모른다” 대신 가장 그럴듯한 값을 만든다

  • 문법·말투는 완벽하다 → 틀린 줄 모른다
  • 우연히 맞아도 출처가 없다 → 검증할 수 없다
  • 해결: 모르는 사실을 입력으로 넣어 준다

최신 모델은 “학교마다 다르니 확인하라”처럼 얼버무리기도 한다. 이것도 실패다: 사용자는 답을 얻지 못했다.

발문: “사람이라면 모를 때 어떻게 하나?” → 문서를 찾아본다 → 그것을 LLM에게 해 주는 것이 RAG.

데모 · 환각 체험

시연 순서

  1. 키 없이: 세 질문을 차례로 고른다. A는 4시간/30%/90% (빨간 ✗), B는 12시간/40%/80% (초록 ✓). 모두 “예시 응답 · 수업용 작성 예시” 표시임을 밝힌다
  2. B 카드의 “보낸 프롬프트”를 펼쳐 근거 문서가 통째로 들어간 것을 보여 준다. 글자 수 비교(A 수십 자 vs B 수백 자)
  3. 교사 키가 있다면 “내 API 키로 직접 비교하기”에서 실제로 호출한다. 키 입력란은 화면 공유 전에 붙여 넣는다

실제 A 답이 우연히 맞으면 오히려 좋은 토론거리다: “맞았는데 왜 믿으면 안 되나?”

RAG = 관련 부분만 찾아서 넣는다

질문 → 검색 → [근거 + 질문] → LLM → 답 + 인용 [1]

오늘 환각 체험의 B는 “검색”을 사람이 대신한 것이다. 4~8주차에 이 검색(청킹·임베딩·벡터스토어·하이브리드 검색·리랭킹)을 직접 만든다.

파인튜닝은 말투·형식을 바꾸는 데 강하고, 사실을 주입하는 데는 비효율적이라는 점만 짧게 언급한다.

관찰 질문

  1. GPU 규정 문장의 한/영 배수는 GPT-2, GPT-4o에서 각각?
  2. 코퍼스 전체는 어느 토크나이저·어느 창에서 넘치나?
  3. A의 숫자는 골든 정답과 얼마나 다른가? 말투는 조심스러운가?
  4. 정답을 얻은 대가로 입력은 몇 배 늘었나?
  5. 골든셋이 없다면 B가 맞았다는 것을 어떻게 확인할까?

1~2는 토큰 카운터 직후 짝 활동 10분. 3~5는 환각 체험 직후 전체 토론.

기대 답: 1) 4.6배 / 1.2배 2) GPT-2가 8,192 창에서 108%로 넘침, 1,024 창은 둘 다 넘침, 128K는 둘 다 들어감 4) 근거 문서만큼 늘어난다(수 배~수십 배) 5) 인용 번호로 원문과 대조 → 11주차 인용 하이라이트, 9주차 Faithfulness.

코드로 확인하기

// 한 글자가 몇 바이트인가? 바이트 단위 BPE 토크나이저가 보는 것은 바이트다
const enc = new TextEncoder();
for (const s of ['token', '토큰', '12시간', 'GPU 서버']) {
  const bytes = enc.encode(s);
  console.log(`${s.padEnd(8)} 문자 ${[...s].length} · 바이트 ${bytes.length} · ${[...bytes].map((b) => b.toString(16)).join(' ')}`);
}
// GPT-2 토크나이저는 '가'(ea b0 80)를 토큰 3개 [166, 108, 222]로 자른다

▶ 실행 결과: token 5문자/5바이트, 토큰 2문자/6바이트, 12시간 4문자/8바이트, GPU 서버 6문자/10바이트.

한글은 음절마다 3바이트다. 바이트 단위 BPE가 이 3바이트를 합친 토큰을 어휘에 갖고 있지 않으면 음절 하나가 토큰 여러 개가 된다. 문자열을 바꿔 다시 실행해 보인다.

C1~C3은 수업 중 모두 끝낸다. C3 코드는 저장해 두라고 한다(7주차). 정답은 부록 B.

정리

  • LLM은 다음 토큰을 예측한다 → 모르면 지어낸다(환각)
  • 토큰 수 = 창 사용량 = 비용. 영어 중심 토크나이저에서 한국어는 4배 넘게 든다
  • 근거를 넣으면 같은 모델도 맞히고, 검증할 수 있다
  • 문서 전체는 못 넣는다 → 관련 부분만 찾아 넣는 것이 RAG

function estimateTokens(text) {
  const hangul = (text.match(/[가-힣]/g) ?? []).length;
  const other = (text.match(/[^\s가-힣]/g) ?? []).length;
  // 한글 음절 = UTF-8 3바이트, GPT-2 어휘는 거의 병합하지 못한다 → 음절당 약 3토큰
  // 영어·숫자·기호는 약 4문자당 1토큰
  return Math.round(hangul * 3 + other / 4);
}

console.table(samples.map((s) => {
  const est = estimateTokens(s.text);
  return { name: s.name, chars: [...s.text].length, est, gpt2: s.gpt2, errPct: Math.round(((est - s.gpt2) / s.gpt2) * 100) };
}));
console.log('GPT-2 한/영 배수:', (161 / 35).toFixed(1), (103 / 24).toFixed(1));
console.log('GPT-4o 한/영 배수:', (43 / 36).toFixed(1), (36 / 29).toFixed(1));

실행 결과: 추정 170/34/94/26 vs 실제 161/35/103/24 → 오차 +6%, −3%, −9%, +8%. 배수: GPT-2 4.6 · 4.3, GPT-4o 1.2 · 1.2.

왜 3인가: 한글 음절은 UTF-8 3바이트이고 GPT-2 어휘는 이 바이트를 거의 합치지 못한다. 실측 계수는 (토큰 − 기타/4) / 음절 = 2.84~3.30이다. 공백은 뒤 단어 토큰에 붙으므로 따로 세지 않는다.

부록 B · C2 정답

const corpusTokens = { gpt2: 8848, gpt4o: 2660 }; // 코퍼스 12문서 전체 (실측)
const windows = [1024, 8192, 128000];
const PRICE_PER_1M = 0.4;   // 가상 단가: 입력 100만 토큰당 0.4달러
const queries = 30 * 20;    // 학생 30명 × 질문 20개
const questionTokens = 20;
const ragTokens = 370;      // 질문 20 + 검색된 청크 3개 350 (가정)

console.table(windows.map((w) => ({
  window: w,
  gpt2Pct: +((corpusTokens.gpt2 / w) * 100).toFixed(1),
  gpt4oPct: +((corpusTokens.gpt4o / w) * 100).toFixed(1),
})));

const stuffTotal = queries * (corpusTokens.gpt4o + questionTokens);
const ragTotal = queries * ragTokens;
const cost = (t) => +((t / 1e6) * PRICE_PER_1M).toFixed(4);
console.table([
  { 방식: '코퍼스 통째로', 총토큰: stuffTotal, 달러: cost(stuffTotal) },
  { 방식: 'RAG(청크 3개)', 총토큰: ragTotal, 달러: cost(ragTotal) },
]);
console.log(`RAG가 ${(stuffTotal / ragTotal).toFixed(1)}배 적게 쓴다`);

const perDoc = corpusTokens.gpt4o / 12;
const bigTokens = Math.round(perDoc * 5000);
console.log(`문서 5,000개 ≈ ${bigTokens.toLocaleString()}토큰 → 128K 창의 ${Math.round((bigTokens / 128000) * 100)}%`);

실행 결과: 창 사용률 GPT-2 864.1% / 108% / 6.9%, GPT-4o 259.8% / 32.5% / 2.1%.

통째로 1,608,000토큰 $0.6432 vs RAG 222,000토큰 $0.0888 → 7.2배. 문서 5,000개 ≈ 1,108,333토큰 → 128K 창의 866%.

단가는 가상 값이다. 금액보다 “비율”이 핵심이라고 강조한다.

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();

function groundedPrompt(question, evidences) {
  const rules = [
    '너는 아래 근거 문서만 사용해 답하는 조교다.',
    '근거에 없는 내용은 추측하지 말고 "문서에서 찾을 수 없다"고 답한다.',
    '문장마다 사용한 근거 번호를 [1]처럼 표기한다.',
  ].join('\n');
  const sources = evidences.length
    ? evidences.map((e, i) => `[${i + 1}] (${e.title})\n${e.text}`).join('\n\n')
    : '(검색된 근거 없음)';
  return `${rules}\n\n### 근거 문서\n${sources}\n\n### 질문\n${question}`;
}

const CLAIM_RE = /\d+(?:\.\d+)?\s*(?:%|퍼센트|시간|교시|학점|호|명|주|회)?/g;
const normalize = (s) => String(s).normalize('NFKC').toLowerCase().replace(/퍼센트/g, '%').replace(/\s+/g, '');

function goldenFacts(answer) {
  const nums = (answer.match(CLAIM_RE) ?? []).map(normalize);
  if (nums.length) return [...new Set(nums)];
  return [normalize(answer).replace(/[.。!]+$/, '').replace(/다$/, '')];
}

function includesFact(t, f) {
  const digitEnd = /\d$/.test(f);
  for (let i = t.indexOf(f); i >= 0; i = t.indexOf(f, i + 1)) {
    const before = t[i - 1] ?? '';
    const after = t[i + f.length] ?? '';
    // "112시간"은 "12시간"이 아니다: 앞뒤가 숫자로 이어지면 다른 수다
    if (!/\d/.test(before) && !(digitEnd && /\d/.test(after))) return true;
  }
  return false;
}

function containsGoldenFact(text, goldenAnswer) {
  const t = normalize(text);
  return goldenFacts(goldenAnswer).every((f) => includesFact(t, f));
}

function mulberry32(seed) {
  return () => {
    seed = (seed + 0x6d2b79f5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
const rand = mulberry32(42);
const bigrams = (s) => new Set([...s.replace(/\s+/g, '')].map((c, i, a) => c + (a[i + 1] ?? '')));

function mockLLM(question, context = null) {
  if (context) {
    const q = bigrams(question);
    const sentences = context.split(/(?<=다\.)\s*/);
    const best = sentences
      .map((s) => ({ s, score: [...bigrams(s)].filter((b) => q.has(b)).length }))
      .sort((a, b) => b.score - a.score)[0].s.trim();
    return { answer: best, cite: best };
  }
  const guesses = ['4시간', '6시간', '8시간', '12시간', '24시간'];
  return { answer: `보통 최대 ${guesses[Math.floor(rand() * guesses.length)]}이다.`, cite: null };
}
