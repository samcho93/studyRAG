🧠 1주차 · LLM 기초 & RAG 필요성

LLM은 우리 학과를 모른다

대규모 언어 모델(LLM, Large Language Model)은 유창하게 답하지만, 배운 적 없는 내용도 자신 있게 지어낸다. 이번 주는 LLM이 글을 읽는 단위인 토큰을 직접 세어 보고, 근거 없이 물을 때와 근거를 붙여 물을 때의 차이를 눈으로 확인한다.

1학습 목표

이번 주가 끝나면
  • LLM이 텍스트를 토큰 단위로 처리한다는 것을 설명하고, 한국어와 영어의 토큰 수 차이를 비용과 컨텍스트 창 사용률로 환산할 수 있다.
  • 환각이 왜 생기는지, 근거 없는 답을 왜 검증할 수 없는지 설명할 수 있다.
  • 질문과 근거 문서로 근거 기반 프롬프트를 만들고, 답이 골든 정답을 포함하는지 판정하는 코드를 작성할 수 있다.

2왜 필요한가

범용 LLM에게 이렇게 물어본다. “실습실에서 GPU 서버를 한 사람이 연속으로 쓸 수 있는 최대 시간은?” 흔히 돌아오는 답은 이런 모양이다.

그럴듯하지만 틀린 답

“대학 실습실의 GPU 서버는 공정한 배분을 위해 보통 1회 4시간 정도로 사용 시간을 제한한다.”

우리 학과 실습실 이용 규정에는 “한 사람이 연속으로 사용할 수 있는 시간은 최대 12시간이다.”라고 적혀 있다. LLM은 이 문서를 학습한 적이 없다. 그래서 “대학 실습실이라면 보통 이렇다”는 패턴으로 빈칸을 채운다. 이것을 환각(hallucination)이라 한다. 더 큰 문제는 답이 우연히 맞더라도 어디서 나온 숫자인지 알 수 없어 검증할 방법이 없다는 점이다.

그럼 학과 문서를 전부 프롬프트에 붙여 넣으면 될까? 우리 문서셋 12개만 해도 GPT-2 토크나이저로 세면 8,848토큰이다. 컨텍스트 창이 8,192토큰인 모델에는 들어가지도 않는다. 실제 학과 문서는 수천 개이고, 넣는 만큼 매번 비용을 낸다.

결론은 하나다. 질문과 관련된 부분만 찾아서 넣어야 한다. 이것이 이 과목 전체의 주제인 검색증강생성(RAG, Retrieval-Augmented Generation)이다.

3개념

LLM은 다음 토큰을 예측한다

LLM은 학습 시점까지 본 텍스트에서 “어떤 토큰 다음에 어떤 토큰이 오는가”를 배운 모델이다. 학습이 끝난 뒤의 정보, 공개되지 않은 조직 내부 문서는 모델 안에 없다. 모르는 것 자체는 정상이다. 문제는 모를 때도 문법적으로 완벽하고 자신 있는 문장을 만든다는 점이다.

토큰과 토크나이저

LLM은 글자를 그대로 읽지 않는다. 토크나이저(tokenizer)가 텍스트를 토큰(token)이라는 조각으로 자르고, 각 조각을 번호로 바꾼 것이 입력이 된다. GPT 계열이 쓰는 바이트 단위 BPE(Byte Pair Encoding)는 텍스트를 UTF-8 바이트로 바꾼 뒤, 학습 데이터에서 자주 붙어 나온 바이트 조합을 하나의 토큰으로 합쳐 어휘를 만든다.

한글 음절 하나는 UTF-8로 3바이트다. 영어 위주로 학습한 GPT-2 어휘에는 한글 바이트 조합이 거의 합쳐져 있지 않아서 음절 하나가 토큰 2~3개로 쪼개진다. 다국어 데이터로 어휘를 만든 GPT-4o 토크나이저는 “서버”, “시간” 같은 단어를 토큰 하나로 가진다. 같은 문장을 실제로 세면 다음과 같다.

문장 (같은 뜻)문자GPT-2GPT-4o
GPU 규정 · 한국어8416143
GPU 규정 · 영어1673536
코퍼스 12문서 전체 · 한국어4,6138,8482,660

GPT-2에서 한국어는 같은 뜻의 영어보다 토큰을 약 4.6배 쓴다. GPT-4o에서는 약 1.2배로 줄어든다. 문자 수만 보면 한국어가 영어의 절반인데도 그렇다.

컨텍스트 창과 비용

컨텍스트 창(context window)은 모델이 한 번에 받을 수 있는 최대 토큰 수다. 시스템 지시, 붙여 넣은 문서, 질문, 그리고 모델이 생성할 답까지 모두 이 안에 들어가야 한다. API 요금도 토큰 수로 매긴다. 그래서 토큰 수는 곧 “얼마나 넣을 수 있는가”이자 “얼마를 내는가”다.

창 사용률 = 입력 토큰 / 창 크기          예) 8,848 / 8,192 = 108% → 넘친다
입력 비용 = 입력 토큰 × (100만 토큰당 단가) / 1,000,000

환각을 줄이는 방법: 근거를 넣어 준다

모델이 모르는 사실은 입력으로 넣어 주면 된다. 프롬프트에 근거 문서를 붙이고 “이 문서만 보고 답하라, 없으면 모른다고 하라”고 지시하면, 모델은 확률 대신 눈앞의 문장을 옮긴다. 답에 근거 번호를 달게 하면 사람이 원문과 대조해 검증할 수 있다.

방법새 정보 반영근거 제시비용
그냥 묻기불가불가가장 싸다
파인튜닝(fine-tuning)재학습해야 반영어렵다학습 비용이 크다

4실습

위젯 두 개로 이번 주 개념을 직접 확인한다. 결과는 오른쪽 실행 결과 창에 실시간으로 표시된다(휴대폰에서는 위젯 바로 아래).

4-1. 토큰 카운터

브라우저 안에서 실제 GPT-4o 토크나이저와 GPT-2 토크나이저를 내려받아 토큰을 센다(최초 1회 약 12MB, 이후 캐시). 문자 수는 바로 나오고 토큰 수는 토크나이저가 준비되면 채워진다. 점선 상자는 여러 토큰이 합쳐져야 글자 하나가 되는 곳이다.

관찰 질문

  1. 처음 문장(GPU 규정)에서 GPT-2와 GPT-4o의 “한국어 토큰 / 영어 토큰” 배수는 각각 얼마인가? 토큰 조각을 GPT-2로 놓고 점선 상자 안의 숫자를 확인한다.
  2. 영어 칸에 “GPU”, “12”처럼 한국어 문장에도 들어 있는 단어가 있다. 이 부분은 두 토크나이저에서 토큰 수가 비슷한가?
  3. 코퍼스 전체 12문서 프리셋을 누른다. 컨텍스트 창을 1,024 → 8,192 → 128,000으로 바꾸며, 어느 토크나이저가 어느 창에서 넘치는지 기록한다.
  4. 한국어 칸에 자기 이름과 학번을 쓰고 토큰 수를 센다. 이름처럼 흔하지 않은 단어는 어떻게 잘리는가?

4-2. 환각 체험

골든셋(assets/data/golden/golden.json)에서 답이 우리 학과 문서에만 있는 질문 세 개를 골랐다. A는 질문만, B는 같은 질문에 근거 문서를 붙여 보낸다. API 키가 없으면 예시 응답 · 수업용 작성 예시가 표시되고, 키를 넣으면 같은 두 프롬프트를 실제 LLM에 보낸다. 키는 이 탭의 sessionStorage에만 저장되고 탭을 닫으면 사라진다.

관찰 질문

  1. 세 질문 모두에서 A의 숫자는 무엇이고 골든 정답과 얼마나 다른가? A의 말투는 틀린 만큼 조심스러운가?
  2. A 카드의 “보낸 프롬프트”와 B 카드의 “보낸 프롬프트”를 펼쳐 글자 수를 비교한다. 정답을 얻은 대가로 입력이 몇 배 늘었나?
  3. (키가 있다면) 실제 LLM의 A 답은 “모른다”고 하는가, 숫자를 지어내는가? “모른다”는 답은 환각보다 나은가, 그래도 부족한가?
  4. B가 맞았다는 것을 우리는 어떻게 확인했나? 골든셋이 없다면 무엇으로 확인할 수 있을까?

function mulberry32(seed) {
  return () => {
    seed = (seed + 0x6d2b79f5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

6정리 & 다음 주 예고

  • LLM은 다음 토큰의 확률을 계산하는 모델이다. 학습하지 않은 사실을 물으면 모른다고 하기보다 그럴듯한 값을 만든다(환각).
  • LLM은 글자가 아니라 토큰을 읽는다. 영어 중심 토크나이저에서 한국어는 같은 뜻의 영어보다 토큰을 4배 넘게 쓰고, 그만큼 창을 빨리 채우고 비용이 든다.
  • 근거 문서를 프롬프트에 넣으면 같은 모델도 정확히 답하고, 답을 원문과 대조해 검증할 수 있다.
  • 문서를 통째로 넣는 방법은 창과 비용의 벽에 막힌다. 관련 부분만 찾아 넣는 것, 이것이 RAG다.

다음 주(2주차 프롬프트 엔지니어링)에는 이번 주 C3에서 만든 근거 기반 프롬프트를 다듬는다. 지시문, 역할, 출력 형식, 예시를 바꾼 두 프롬프트를 A/B로 비교하며, 같은 근거로도 프롬프트에 따라 답의 정확도와 형식이 어떻게 달라지는지 본다. 2주차는 LLM API 키가 필요하다.
