골든셋 = 질문 · 정답 · 근거

{ "question": "GPU 서버를 연속으로 쓸 수 있는 최대 시간은?",
  "answer":   "최대 12시간이다.",
  "evidence": [{ "doc": "facility-rules",
     "quote": "…연속으로 사용할 수 있는 시간은 최대 12시간이다." }] }
  • 근거는 원문 구간(quote)까지 — 원문에 있는지 코드로 검사
  • 질문은 사용자처럼 — 원문을 베끼면 BM25에 유리한 시험
  • 망가진 문서 · 숫자 답 · 여러 근거를 섞는다

발문: “우리 골든셋 질문 중 원문 단어를 거의 그대로 쓴 것은?” (q07 “RRF에서 k 값”, q08 “Faithfulness” 등) → BM25가 이 골든셋에서 유리하다는 편향을 스스로 찾게 한다.

C2에서 겹침 비율 0.6 초과를 “베낌”으로 잡는다. n02 초안은 겹침 0.78로 걸린다.

손으로 계산하기 · 정답 {A, C}

순위청크1/log₂(i+1)
1B1.000
2A ✓0.631
3D0.500
4C ✓0.431
5E0.387

P@3 = 1/3 = 0.333

R@3 = 1/2 = 0.500 · R@5 = 1.0

RR = 1/2 = 0.500

nDCG@5 = 1.062 / 1.631 = 0.651

nDCG@3 = 0.631 / 1.631 = 0.387

표 왼쪽만 먼저 보여 주고 오른쪽 숫자는 학생이 계산하게 한다(3분). 오른쪽은 가리기(B)로 가렸다가 공개한다.

IDCG는 “정답 2개를 1·2위에 몰아 둔 경우” = 1 + 0.631. 정답 수가 k보다 많으면 IDCG는 k개까지만 더한다는 점을 C1에서 확인한다.

MRR은 k와 무관하게 전체 순위로 계산한다(core/metrics.js 구현도 동일). 그래서 위젯에서 k를 바꿔도 MRR은 변하지 않는다.

코드로 확인하기

import { chunk } from '/assets/js/core/chunker.js';
import { BM25 } from '/assets/js/core/bm25.js';
import { evaluate } from '/assets/js/core/metrics.js';
const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const golden = await (await fetch('/assets/data/golden/golden.json')).json();

const cfg = { strategy: 'recursive', size: 200, overlap: 0 }; // 바꿔 보기
const chunks = corpus.documents.flatMap((d) =>
  chunk(d.text, cfg).map((c) => ({ id: `${d.id}#${c.index}`, text: c.text })));
const bm25 = new BM25().add(chunks);

const runs = golden.items.map(({ id, question, evidence: [ev] }) => {
  const hits = bm25.search(question, chunks.length);
  const i = hits.findIndex((h) => h.text.includes(ev.quote)); // 근거 단위 정답
  console.log(id, i === -1 ? '근거 없음' : `${i + 1}위`);
  return { retrieved: hits.map((h, j) => (j === i ? 'EV' : h.id)), relevant: ['EV'] };
});
console.table(evaluate(runs, 3));

▶ 실행하면 q09 4위, q10 12위와 recall 0.833 · mrr 0.861 · ndcg 0.833이 나온다(위젯 처음 화면과 같다).

cfg의 size를 100, strategy를 'fixed'로 바꿔 다시 실행한다 → 근거 없음 5개 + q09 근거 없음(검색 안 됨), recall 0.5.

부록 B · C1 정답

import { precisionAtK, recallAtK, hitAtK, reciprocalRank, ndcgAtK } from '/assets/js/core/metrics.js';

const retrieved = ['d7', 'd2', 'd4', 'd5', 'd1', 'd9', 'd3'];
const relevant = ['d2', 'd5', 'd9'];
const k = 5;

// 상위 5개: d7 ✗, d2 ✓(2위), d4 ✗, d5 ✓(4위), d1 ✗  → 정답 2개
// DCG  = 1/log2(3) + 1/log2(5) = 0.631 + 0.431 = 1.062
// IDCG = 1 + 1/log2(3) + 1/log2(4) = 1 + 0.631 + 0.5 = 2.131 (정답 3개를 1~3위에)
const mine = { precision: 2 / 5, recall: 2 / 3, hit: 1, rr: 1 / 2, ndcg: 1.062 / 2.131 };

const lib = {
  precision: precisionAtK(retrieved, relevant, k),
  recall: recallAtK(retrieved, relevant, k),
  hit: hitAtK(retrieved, relevant, k),
  rr: reciprocalRank(retrieved, relevant),
  ndcg: ndcgAtK(retrieved, relevant, k),
};
console.table(Object.keys(lib).map((m) => ({ metric: m, mine: +mine[m].toFixed(3), lib: +lib[m].toFixed(3), ok: Math.abs(mine[m] - lib[m]) < 0.001 })));

// d9와 d1의 자리를 바꾸면 d9가 5위로 들어온다
const swapped = ['d7', 'd2', 'd4', 'd5', 'd9', 'd1', 'd3'];
console.log('swap → recall', recallAtK(swapped, relevant, k).toFixed(3),
  'precision', precisionAtK(swapped, relevant, k).toFixed(3),
  'ndcg', ndcgAtK(swapped, relevant, k).toFixed(3), 'rr', reciprocalRank(swapped, relevant));

기대 출력: precision 0.4 · recall 0.667 · hit 1 · rr 0.5 · ndcg 0.498 모두 ok=true. 자리 바꿈 후 recall 1.000, precision 0.600, ndcg 0.680, rr 0.5(그대로).

왜: IDCG에서 정답이 3개이므로 1~3위를 채운 1 + 0.631 + 0.5 = 2.131로 나눈다. 학생들이 가장 많이 틀리는 곳은 IDCG를 “상위 5개 중 정답 2개”로 계산하는 것이다. 이상적 순서는 검색 결과가 아니라 정답 집합에서 만든다.

손계산 1.062/2.131 = 0.4984와 라이브러리 0.4982의 차이는 반올림 때문이다(허용 오차 0.001).

/** 질문 단어 중 quote에도 있는 단어의 비율 */
function overlap(question, quote) {
  const q = new Set(tokenize(question, { bigrams: false }));
  const e = new Set(tokenize(quote, { bigrams: false }));
  if (q.size === 0) return 0;
  return [...q].filter((t) => e.has(t)).length / q.size;
}

function validate(item) {
  const problems = [];
  if (!item.question?.trim() || !item.answer?.trim()) problems.push('질문/정답 비어 있음');
  for (const ev of item.evidence ?? []) {
    const doc = docById[ev.doc];
    if (!doc) { problems.push(`문서 없음: ${ev.doc}`); continue; }
    if (!doc.text.includes(ev.quote)) problems.push(`quote가 원문에 없음: "${ev.quote.slice(0, 20)}…"`);
    const ov = overlap(item.question, ev.quote);
    if (ov > 0.6) problems.push(`질문이 근거를 베꼈다 (겹침 ${ov.toFixed(2)})`);
  }
  if (!item.evidence?.length) problems.push('근거 없음');
  return problems;
}

const PARTICLES = ['에서', '으로', '까지', '부터', '은', '는', '이', '가', '을', '를', '에', '의', '로', '도', '다'];
const STOP = new Set(['있다', '없다', '한다', '된다']); // 사실을 담지 않는 말
function keyTokens(sentence) {
  const words = sentence.toLowerCase().match(/[\p{L}\p{N}%]+/gu) ?? [];
  return words
    .map((w) => {
      const p = PARTICLES.find((s) => w.endsWith(s) && w.length - s.length >= 2);
      return p ? w.slice(0, -p.length) : w;
    })
    .filter((w) => w.length >= 2 && !STOP.has(w));
}

function faithfulness(answer, context) {
  // 활용형 차이(인정된 ↔ 인정됩니다)는 마지막 글자를 뗀 어간으로 한 번 더 찾는다
  const found = (t) => context.includes(t) || (t.length >= 3 && context.includes(t.slice(0, -1)));
  const sentences = sentenceSpans(answer).map(([s, e]) => answer.slice(s, e).trim()).filter(Boolean).map((text) => {
    const missing = keyTokens(text).filter((t) => !found(t));
    return { text, missing, supported: missing.length === 0 };
  });
  const score = sentences.filter((x) => x.supported).length / (sentences.length || 1);
  return { score, sentences };
}
