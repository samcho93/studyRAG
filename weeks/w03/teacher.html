성적 우수 장학금 지급액은?

스캔한 안내문을 OCR로 뽑은 텍스트

한국폴리텍대학 분당융합기술교육원     - 1 -
2025학년도 장 학 금 안 내
… 평균 평 점이 4.0 이상인 학생에게 지급한 다.
지급액은 수업료의 5O% 이다.

이상한 곳을 모두 찾아보자. 몇 군데인가?

발문: “이 텍스트에서 이상한 곳을 전부 찾아라.” 1분 준다.

기대 답: 머리글 반복(- 1 -), “장 학 금 안 내” 공백, “평 점이”, “지급한 다”, 그리고 가장 찾기 어려운 5O%(영문 O). 5O%를 못 찾는 학생이 많다 — 사람 눈에도 안 보이는 오류가 기계에는 전혀 다른 토큰이라는 점이 오늘의 출발점이다.

망가진 한 글자가 끝까지 간다

검색질문 “50%” → 토큰 50 · 문서 “5O%” → 토큰 5o → 불일치
생성검색되어도 “5O%”를 그대로 인용하거나 “알 수 없다”
평가골든셋 근거 인용문도 「… 5O% 이다.」 — 정답지까지 오염

파싱에서 사라진 정보는 어떤 단계도 되살리지 못한다

평가 행이 중요하다. golden.json의 q11 evidence.quote가 실제로 “5O%”로 기록되어 있다. 파싱을 고치면 골든셋도 같이 고쳐야 한다 → 9주차 평가에서 다시 나온다.

시간표(q10)도 같은 구조의 실패라고 한 줄 언급하고 넘어간다. 데모에서 보여 준다.

로더: 원본마다 방법이 다르다

원본방법흔한 깨짐도구 예
텍스트층 PDF저장된 글자·좌표 읽기읽기 순서, 머리글 반복pdf.js, PyMuPDF
스캔 PDFOCR로 글자 추정0↔O, 1↔l, 음절 공백Tesseract
HTMLDOM 파싱메뉴·푸터, 중복 블록DOMParser, BeautifulSoup
표행·열 구조 읽기셀이 한 줄로 이어짐pdfplumber, Camelot

통합 도구: Unstructured — 요소(제목·본문·표)로 나누고 메타데이터를 붙인다

발문: “PDF 파일을 열어 Ctrl+A, Ctrl+C가 되면 어느 종류고, 안 되면 어느 종류인가?” → 복사되면 텍스트층, 안 되면 스캔(그림). 가장 쉬운 판별법이다.

도구는 소개만 한다. 이 사이트는 설치 없는 브라우저 실습이 원칙이라 PDF 라이브러리를 쓰지 않고, 문서셋에 “로더 출력”을 저장해 두었다고 설명한다.

메타데이터: 조각이 어디서 왔는가

{ "text": "지급액은 수업료의 50% 이다.",
  "metadata": { "source": "broken-scan", "page": 1, "loader": "ocr" } }
  • 인용 — “장학금 안내 1쪽”
  • 필터 — 특정 문서·연도만 검색
  • 디버깅 — 틀린 답의 출처 추적
  • 갱신 — 바뀐 문서만 재임베딩

쪽 번호는 지우기 전에 메타데이터로 옮긴다 (C5)

“쪽 번호는 잡음이면서 정보다”라는 역설을 강조한다. 정제 단계에서 지우는 바로 그 줄이 page 메타데이터의 유일한 출처다.

11주차 인용 하이라이트, 7주차 최소 RAG의 “출처 표시”가 모두 여기서 시작한다.

정제 규칙에는 부작용이 있다

단계고치는 것잘못 쓰면
머리글·바닥글반복 줄, 메뉴·저작권반복된 본문까지 삭제
중복 문단같은 Q&A 2번—
표 행 복원요일+교시로 행 분리패턴 밖의 행은 추측
OCR 숫자5O% → 50%MLOps → ML0ps
공백 병합“평 점이” → 평점이“조 교수” → 조교수

규칙은 문서 종류별로 켠다 · 결과는 사실로 검증한다

“조 교수 → 조교수”에서 웃음이 나오면 성공이다. 뜻이 바뀌는(교수 이름 → 직급) 실제 사례다.

공백 병합의 한계: 사전 없이 규칙만으로는 “결석 시 보강”과 “시 간당”을 구별할 수 없다. 실무는 형태소 분석기나 띄어쓰기 교정 모델을 쓴다고 언급한다.

파싱 품질은 상한이다

정답률 ≤ 파싱 × 청킹 × 검색 × 생성

  • 골든셋 12문항 중 q10(표) · q11(OCR) 근거가 깨짐
  • 파싱 보존율 10/12 → 뒤가 완벽해도 최대 83%
  • 4~9주차의 어떤 튜닝도 이 천장을 못 올린다

엄밀한 공식이 아니라 “곱으로 줄어든다”는 직관이다. 각 단계가 90%면 0.9⁴ ≈ 66%라는 것도 같이 계산해 보인다.

발문: “RAG가 틀렸을 때 어디부터 봐야 하나?” → 파싱 결과부터. 9주차 평가 토론의 복선이다.

데모 · 파싱 정제 뷰어

시연 순서 (결과는 오른쪽 실행 결과 창에 실시간으로 나온다)

  1. 처음 화면: 장학금 스캔본, 모두 끔 → 사실 0/5 (5O%, 평 점이, 1O시간, 2l4, 머리글)
  2. OCR 숫자 교정만 켠다 → 3건 교정, 3/5. 원문 쪽 빨간 O와 정제본 쪽 초록 0을 짚는다
  3. “권장 설정” → 5/5. 머리글 2줄, 쪽 번호 2건, 공백 병합 7건
  4. “전부 켜기” → 2/5. 한글 사이 공백 전부 제거가 문장을 망가뜨린다
  5. 문서를 2학기 시간표로 → 모두 끔 0/3, 표 행 복원 켜면 8행 3/3. 여기서 “과도: 모든 O→0”을 켜면 MLOps → ML0ps
  6. 자주 묻는 질문 → 머리글·바닥글만 켜면 노트북 Q&A가 0번(둘 다 삭제). 중복 문단 제거를 켜면 복구 → 순서 이야기

3번 정답: 추측이다. 원문에는 강의실 번호도 담당도 없다. 규칙이 “외부”라는 단어에서 강의실 칸을 시작했을 뿐이다. 표는 텍스트로 복원하는 것보다 로더가 <td>를 읽는 쪽이 근본 해결이라는 결론(6번)으로 이어 간다.

5번 정답: 머리글 규칙은 “2번 이상 반복된 줄”이므로, 중복된 Q와 A 줄을 머리글로 오인한다. 중복 제거가 먼저 돌면 반복이 사라져 오인하지 않는다.

부록 B · C1 정답

const pages = [
  '한국폴리텍대학 분당융합기술교육원 - 1 -\n2025학년도 장학금 안내\n성적 우수 장학금 지급액은 수업료의 50%다.\n교무처 | 무단 전재 금지',
  '한국폴리텍대학 분당융합기술교육원 - 2 -\n가계 곤란 장학금은 소득 3분위 이하가 대상이다.\n교무처 | 무단 전재 금지',
  '한국폴리텍대학 분당융합기술교육원 - 3 -\n근로 장학생은 주 10시간 이내로 일한다.\n교무처 | 무단 전재 금지',
];
const norm = (line) => line.replace(/\d+/g, '#').replace(/\s+/g, ' ').trim();

function removeRepeated(pages, minRatio = 0.5) {
  const pageCount = new Map();
  for (const page of pages) {
    const seen = new Set(page.split('\n').map(norm).filter(Boolean));
    for (const key of seen) pageCount.set(key, (pageCount.get(key) ?? 0) + 1);
  }
  const need = Math.max(2, Math.ceil(pages.length * minRatio));
  const repeated = new Set([...pageCount].filter(([, n]) => n >= need).map(([k]) => k));
  const cleaned = pages.map((page) =>
    page.split('\n').filter((line) => !repeated.has(norm(line))).join('\n'));
  return { cleaned, repeated: [...repeated] };
}
const { cleaned, repeated } = removeRepeated(pages);
console.log('반복으로 판정된 줄:', repeated);
cleaned.forEach((p, i) => console.log(`--- ${i + 1}쪽\n${p}`));

실행 결과: 반복 줄 2개 — '한국폴리텍대학 분당융합기술교육원 - # -', '교무처 | 무단 전재 금지'. 각 쪽에 본문만 남는다.

왜: 숫자를 #으로 바꾸지 않으면 “- 1 -”과 “- 2 -”가 다른 줄이 되어 머리글을 못 찾는다. “쪽 수”로 세는 이유는 한 쪽 안에서 우연히 반복된 줄(예: 같은 문장 두 번)을 머리글로 오인하지 않기 위해서다. Math.max(2, …)는 1쪽짜리 문서에서 모든 줄이 지워지는 것을 막는다.

부록 B · C2 정답

const cases = [
  ['지급액은 5O%', '지급액은 50%'], ['주 1O시간', '주 10시간'], ['내선 2l4', '내선 214'],
  ['2OO5년', '2005년'], ['MLOps 과목', 'MLOps 과목'], ['Model1 결과', 'Model1 결과'],
  ['COVID19', 'COVID19'], ['CO2 배출', 'CO2 배출'], ['Hello World', 'Hello World'],
];
// 숫자를 하나 이상 포함하고 [0-9OoIl]로만 된 덩어리. 앞뒤가 영문자면(= 단어의 일부) 제외
const OCR_RUN = /(?<![A-Za-z])[0-9OoIl]*\d[0-9OoIl]*(?![A-Za-z])/g;

function fixOcr(text) {
  return text.replace(OCR_RUN, (run) => run.replace(/[Oo]/g, '0').replace(/[Il]/g, '1'));
}

const naive = (t) => t.replace(/O/g, '0').replace(/l/g, '1');
let pass = 0;
for (const [input, want] of cases) {
  const got = fixOcr(input);
  if (got === want) pass++;
  console.log(got === want ? '✓' : '✗', input, '→', got, '| naive:', naive(input));
}
console.log(`${pass}/${cases.length} 통과`);

실행 결과: 9/9 통과. naive는 ML0ps, Mode11, C0VID19, C02, He11o Wor1d로 5개를 망가뜨린다.

왜: 글자 단위로 “숫자 옆의 O·l”만 보는 /(?<=\d)[Ol]|[Ol](?=\d)/는 CO2 → C02, Model1 → Mode11로 망가뜨리고, 2OOO5처럼 O가 셋 이상이면 가운데를 놓친다. 덩어리 단위로 잡고 덩어리 전체가 영문자에 붙어 있지 않은지 확인해야 두 문제가 함께 풀린다.

남는 한계: 영문 약어 자체가 OCR로 깨진 경우(IoT → 1oT)는 규칙으로 판단할 수 없다. 사전·문맥이 필요하다.

    if (seen.has(key)) removed.push(key.slice(0, 20) + '…');
    else {
      seen.add(key);
      kept.push(para.trim());
    }
  }
  return { text: kept.join('\n\n'), removed };
}
const before = doc.text.split(/\n\s*\n/).length;
const { text, removed } = dedupeParagraphs(doc.text);
console.log(`문단 ${before}개 → ${text.split('\n\n').length}개`);
console.log('지운 문단:', removed);
console.log(text);

실행 결과: 문단 5개 → 4개. 지운 문단 'Q. 노트북을 가져와도 되나요? A.…'. 메뉴(“홈 | 학과소개 | … | 로그인”)와 저작권 줄은 남는다.

왜 메뉴가 남나: 한 번만 나오기 때문이다. 중복 제거는 “같은 것 두 번”만 잡는다. 메뉴·푸터는 키워드 규칙이나, 더 근본적으로는 HTML 로더가 <nav>·<footer>를 버려야 한다.

확장 토론: 공백만 다른 중복은 key 정규화로 잡힌다. 한 글자만 다른 “거의 중복”은? → 해시(MinHash) 또는 임베딩 유사도(5주차).

function parseTimetable(text) {
  const lines = text.split('\n');
  const h = lines.findIndex((l) => /^요일\s+교시\s+과목\s+강의실\s+담당$/.test(l.trim()));
  return lines[h + 1].split(/\s+(?=[월화수목금토일]\s+\d+-\d+\s)/).map((row) => {
    const [, day, period, rest] = row.match(/^([월화수목금토일])\s+(\d+-\d+)\s+(.*)$/);
    const toks = rest.split(/\s+/);
    let teacher = null;
    if (toks.at(-1) === '공동') teacher = toks.pop();
    else if (toks.at(-1) === '교수') teacher = toks.splice(-2).join(' ');
    let r = toks.findIndex((t) => /^\d{3}$/.test(t));
    if (r < 0) r = toks.indexOf('외부'); // 강의실 번호가 없는 행: 장소 단어에서 자른다(추측)
    return { day, period, subject: toks.slice(0, r).join(' '), room: toks.slice(r).join(' '), teacher };
  });
}

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();

const fixOcr = (t) =>
  t.replace(/(?<![A-Za-z])[0-9OoIl]*\d[0-9OoIl]*(?![A-Za-z])/g, (r) => r.replace(/[Oo]/g, '0').replace(/[Il]/g, '1'));

function splitPages(text) {
  const pages = [];
  for (const line of text.split('\n')) {
    const m = line.match(/-\s*(\d+)\s*-\s*$/);
    if (m) pages.push({ page: Number(m[1]), lines: [] }); // 머리글 줄은 버리고 쪽 번호만 기억
    else if (pages.length) pages.at(-1).lines.push(line);
  }
  return pages.map((p) => ({ page: p.page, text: p.lines.join('\n').trim() }));
}
const chunks = splitPages(doc.text).flatMap(({ page, text }) =>
  chunk(fixOcr(text), { strategy: 'sentence', size: 80 }).map((c) => ({
    id: `${doc.id}#p${page}-c${c.index}`,
    text: c.text.trim(),
    metadata: { source: doc.id, title: doc.title, page, start: c.start, end: c.end },
  })));
console.table(chunks.map((c) => ({ id: c.id, page: c.metadata.page, text: c.text.slice(0, 30) })));
for (const q of ['50%', '10시간']) {
  const hit = chunks.find((c) => c.text.includes(q));
  console.log(`「${q}」 → ${hit.metadata.title} ${hit.metadata.page}쪽`);
}

실행 결과: 청크 4개(p1-c0, p1-c1, p1-c2, p2-c0). 「50%」 → 1쪽, 「10시간」 → 2쪽.

왜: 쪽 번호 줄을 지우는 순간 페이지 정보가 사라지므로, 지우기 전에 페이지 단위로 나눠 두고 청크마다 page를 복사한다.

짚을 점: 여기서 start/end는 “정제된 페이지 텍스트” 기준이다. 원문 기준 위치가 필요하면(11주차 하이라이트) 정제 과정에서 위치 매핑을 따로 유지해야 한다. 메타데이터에 기준을 명시하라고 지도한다.
