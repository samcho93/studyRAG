임베딩: 문장 → 방향

  • 문장 → 고정 길이 실수 벡터 (오늘 모델: 384차원)
  • 뜻이 가까운 쌍은 가까운 방향이 되도록 학습
  • 질문도 같은 모델로 벡터화 → 가장 가까운 청크
"청킹은 문장을 자른다"
  → [0.021, -0.113, 0.087, …]  (384개)
"랩실에서 먹으면 안 된다"
  → [-0.054, 0.032, 0.140, …]

숫자 하나하나에 사람이 읽을 뜻은 없다

벡터 값은 예시(가짜)라고 분명히 말한다. 개별 차원에 “청킹 축” 같은 의미가 있다는 오해를 막는다. Challenge에서 쓰는 4차원 벡터는 설명용으로 축에 이름을 붙인 장난감이라고 미리 알린다.

“같은 모델” 강조: 문서와 질문을 다른 모델로 임베딩하면 비교 자체가 무의미하다.

가까움을 재는 세 가지 방법

척도식보는 것함정
코사인a·b / (‖a‖‖b‖)각도길이 무시
내적Σ aᵢbᵢ각도 × 길이긴 벡터가 유리
유클리드‖a − b‖끝점 거리길이 다르면 멀다

정규화(‖v‖ = 1) 하면: cos = a·b, ‖a − b‖² = 2 − 2cos → 순위가 같다

칠판에 2 − 2cos를 유도한다: ‖a−b‖² = ‖a‖² + ‖b‖² − 2a·b, 길이 1이면 2 − 2a·b.

발문: “그럼 벡터스토어는 셋 중 무엇을 계산하면 제일 빠를까?” → 내적(나눗셈·제곱근 없음). vectorstore.js가 저장 시 정규화하는 이유다.

코드로 확인: 길이의 함정

import { dot, cosine } from '/assets/js/core/vectorstore.js';

const q = [0.8, 0.2, 0.0, 0.1];       // "청킹이란?"
const chunk = [0.9, 0.1, 0.0, 0.1];   // 정답 청크
const long = [3.0, 2.4, 0.3, 0.6];    // 긴 잡탕 문서
const unit = (v) => { const l = Math.hypot(...v); return v.map((x) => x / l); };

console.table([
  { doc: '정답 청크', dot: dot(q, chunk), cosine: cosine(q, chunk), unitDot: dot(unit(q), unit(chunk)) },
  { doc: '긴 잡탕 문서', dot: dot(q, long), cosine: cosine(q, long), unitDot: dot(unit(q), unit(long)) },
]);

▶ 실행 결과: 정답 청크 dot 0.75 / cos 0.991, 긴 잡탕 문서 dot 2.94 / cos 0.908. 내적만 보면 긴 문서가 1위, 코사인은 정답 청크가 1위. unitDot 열은 cosine 열과 같다.

4주차 연결: “문서를 통째로 넣으면 평균 벡터가 된다”와 같은 이야기. 임베딩 모델이 이미 정규화해 주면 이 함정은 사라진다. 직접 만든 벡터나 정규화하지 않는 API를 쓸 때 조심한다.

e5 모델의 약속: query: / passage:

  • 학습 때 질문에 query: , 문서에 passage: 를 붙였다 → 사용할 때도 붙인다
  • 문장 ↔ 문장 비교(대칭)는 양쪽 모두 query:
  • 빠뜨려도 오류가 안 난다 — 점수만 조용히 나빠진다
  • e5 코사인은 원래 0.7~1.0 근처에 몰린다 → 순위로 판단

embed.js는 role에 따라 접두어를 자동으로 붙인다

모델 선택과 차원

언어

  • 영어 전용 모델 + 한국어 → 토큰이 망가짐 → 모든 문장이 비슷
  • 다국어 또는 한국어 추가 학습 모델을 쓴다

차원

  • 384차원 × 4바이트 = 1.5KB / 벡터
  • 100만 청크: 384 → 1.5GB, 1024 → 4.1GB
  • 크다고 한국어를 잘하는 게 아니다

실무 모델 비교(KURE · BGE-M3 · OpenAI): 이론 페이지 “한국어 임베딩 모델 비교”

계산: 384×4 = 1,536B, ×10⁶ ≈ 1.54GB. 1024×4×10⁶ ≈ 4.1GB. 6주차 인덱스 이야기의 복선.

이론 페이지(theory/embedding-models.html)는 과제로 읽게 한다. 모델 이름과 수치는 바뀌므로 “고르는 기준”을 가져가게 한다.

5번: PCA 설명 비율이 50% 안팎이면 절반의 정보를 버린 그림이다.

384차원을 2D로: PCA + 거듭제곱법

1. 평균을 뺀다 (중심화)
2. v ← normalize(Xᵀ(X v)) 반복 → PC1  (분산이 가장 큰 방향)
3. PC1 성분을 빼 가며 같은 반복 → PC2
4. 점 = (x·PC1, x·PC2)

반복할수록 v가 가장 “늘어나는” 방향으로 끌려간다

두 축이 설명하는 분산 비율을 반드시 같이 본다

직관: 공분산 행렬을 곱할 때마다 가장 큰 고유값 방향 성분이 상대적으로 커진다. 고유값 분해 라이브러리 없이 곱셈만으로 된다는 점이 핵심.

공분산 행렬(384×384)을 만들지 않고 Xᵀ(Xv)로 계산하면 N이 작을 때 훨씬 싸다. C5가 이것이다.

부록 B · C1 정답

const v = {
  청킹: [0.9, 0.1, 0.0, 0.1],
  오버랩: [0.8, 0.2, 0.1, 0.0],
  장학금: [0.1, 0.0, 0.9, 0.1],
  영벡터: [0, 0, 0, 0],
};
function dot(a, b) {
  let s = 0;
  for (let i = 0; i < a.length; i++) s += a[i] * b[i];
  return s;
}
function norm(a) {
  return Math.sqrt(dot(a, a));
}
function cosine(a, b) {
  const d = norm(a) * norm(b);
  return d === 0 ? 0 : dot(a, b) / d;
}
console.log('청킹·오버랩', cosine(v.청킹, v.오버랩).toFixed(3));
console.log('청킹·장학금', cosine(v.청킹, v.장학금).toFixed(3));
console.log('청킹·영벡터', cosine(v.청킹, v.영벡터));

기대 출력: 청킹·오버랩 0.978, 청킹·장학금 0.120, 청킹·영벡터 0.

왜: 영벡터는 방향이 없으므로 코사인이 정의되지 않는다. NaN을 그대로 돌려주면 정렬이 깨진다(NaN 비교는 항상 false). 0을 돌려주는 것이 vectorstore.js와 같은 선택이다.

부록 B · C2 정답

const docs = { 청킹: [0.9, 0.1, 0.0, 0.1], 실습실: [0.1, 0.9, 0.1, 0.1], 긴문서: [3.0, 2.4, 0.3, 0.6] };
const q = [0.8, 0.2, 0.0, 0.1];
const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);
const norm = (a) => Math.sqrt(dot(a, a));
const cosine = (a, b) => dot(a, b) / (norm(a) * norm(b));
const normalize = (a) => { const l = norm(a); return a.map((x) => x / l); };
const euclid = (a, b) => Math.sqrt(a.reduce((s, x, i) => s + (x - b[i]) ** 2, 0));

const qn = normalize(q);
const rows = Object.entries(docs).map(([id, d]) => {
  const dn = normalize(d);
  return {
    id,
    rawDot: dot(q, d), cosine: cosine(q, d),
    unitDot: dot(qn, dn), euclidUnit: euclid(qn, dn),
    '2−2cos': 2 - 2 * cosine(q, d), 'euclid²': euclid(qn, dn) ** 2,
  };
});
console.table(rows);
const top = (k) => rows.reduce((a, b) => (b[k] > a[k] ? b : a)).id;
console.log('내적 1위:', top('rawDot'), '/ 코사인 1위:', top('cosine'));

기대 출력: rawDot 청킹 0.75 · 실습실 0.27 · 긴문서 2.94 / cosine 0.991 · 0.355 · 0.908. unitDot = cosine. 2−2cos 열과 euclid² 열이 소수점 15자리까지 같다(0.0179, 1.2907, 0.1850). “내적 1위: 긴문서 / 코사인 1위: 청킹”.

왜: 정규화하면 길이 정보가 사라져 세 척도가 모두 각도만의 함수가 된다. 그래서 순위가 같다.

부록 B · C3 정답

import { VectorStore } from '/assets/js/core/vectorstore.js';
const docs = [
  { id: 'chunk-fixed', vector: [0.9, 0.1, 0.0, 0.1] },
  { id: 'chunk-overlap', vector: [0.8, 0.2, 0.1, 0.0] },
  { id: 'lab-food', vector: [0.1, 0.9, 0.1, 0.1] },
  { id: 'lab-hours', vector: [0.0, 0.8, 0.0, 0.3] },
  { id: 'sch-grade', vector: [0.1, 0.0, 0.9, 0.1] },
  { id: 'sch-work', vector: [0.0, 0.2, 0.8, 0.2] },
  { id: 'lunch', vector: [0.1, 0.1, 0.1, 0.9] },
];
const query = [0.2, 0.7, 0.1, 0.4];
const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);
const cosine = (a, b) => dot(a, b) / Math.sqrt(dot(a, a) * dot(b, b));

function topK(q, items, k = 3) {
  return items
    .map(({ id, vector }) => ({ id, score: cosine(q, vector) }))
    .sort((a, b) => b.score - a.score)
    .slice(0, k);
}
const mine = topK(query, docs, 3);
console.table(mine);
const store = new VectorStore();
store.addMany(docs);
const ref = store.search(query, 3);
console.table(ref.map(({ id, score }) => ({ id, score })));
console.log('같은 순서:', mine.every((r, i) => r.id === ref[i].id));

기대 출력: lab-hours 0.951, lab-food 0.913, lunch 0.600. VectorStore도 같은 순서(점수 차이는 Float32 반올림 때문에 1e-8 수준). “같은 순서: true”.

const X0 = [
  [0.9, 0.1, 0.0, 0.1], [0.8, 0.2, 0.1, 0.0], [0.1, 0.9, 0.1, 0.1], [0.0, 0.8, 0.0, 0.3],
  [0.1, 0.0, 0.9, 0.1], [0.0, 0.2, 0.8, 0.2], [0.1, 0.1, 0.1, 0.9],
];
const n = X0.length, d = X0[0].length;
const dot = (a, b) => a.reduce((s, x, i) => s + x * b[i], 0);
const unit = (v) => { const l = Math.sqrt(dot(v, v)); return v.map((x) => x / l); };

const mean = Array.from({ length: d }, (_, k) => X0.reduce((s, r) => s + r[k], 0) / n);
const X = X0.map((r) => r.map((x, k) => x - mean[k]));
const total = X.reduce((s, r) => s + dot(r, r), 0);
const covMul = (v) => {
  const out = new Array(d).fill(0);
  for (const r of X) { const p = dot(r, v); for (let k = 0; k < d; k++) out[k] += p * r[k]; }
  return out;
};
const orth = (v, comps) => comps.reduce((w, c) => { const p = dot(w, c); return w.map((x, k) => x - p * c[k]); }, v);

function powerIteration(comps, iters = 500) {
  let v = unit(orth([1, 0.9, 0.8, 0.7], comps));
  for (let t = 0; t < iters; t++) {
    const w = unit(orth(covMul(v), comps));
    const diff = w.reduce((s, x, k) => s + (x - v[k]) ** 2, 0);
    v = w;
    if (diff < 1e-12) break;
  }
  return v;
}
const pc1 = powerIteration([]);
const pc2 = powerIteration([pc1]);
const ev = [pc1, pc2].map((c) => dot(c, covMul(c)) / total);
console.log('설명된 분산:', ev.map((e) => (e * 100).toFixed(1) + '%').join(', '));
console.log('직교 확인 pc1·pc2 =', dot(pc1, pc2).toExponential(1));
console.table(X.map((r, i) => ({ id: `S${i + 1}`, pc1: +dot(r, pc1).toFixed(3), pc2: +dot(r, pc2).toFixed(3) })));
