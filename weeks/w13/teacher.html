발문: “친구에게 ‘주말에는?’이라고 물으면 친구는 어떻게 알아듣나?” → 앞 대화가 주제를 채운다. 검색기는 네 글자만 받는다.

“주말에는?” 원문 검색 상위 3은 도서관(5.29)·학사 행정(5.16)·통학 버스(5.13)다. 실습실 규정은 3위 안에 없다. “신청은…”은 기숙사(7.76)가 1위, 실습실 규정은 2위(6.27)다.

11주차 인용 검증기로도 못 잡는다는 점을 짚는다. 문장은 출처와 일치한다.

기록 전체를 검색어에 붙이면? → 주제가 섞여 점수가 흐려진다 (4주차 “큰 청크”)

검색·생성·인용 코드는 그대로이고, 검색 앞에 한 단계가 더해질 뿐이라는 점을 그림으로 그린다(판서: D 키).

발문: “기록을 통째로 검색하면 안 되나?” 기대 답: 세 질문의 단어가 섞여 엉뚱한 문서가 올라온다.

condense 프롬프트

[system] 대화 기록과 마지막 질문을 읽고, 기록 없이도 뜻이 통하는
검색용 독립 질문 한 문장으로 다시 쓴다. 대명사·생략을 구체적인 이름으로.
답하지 말고 질문만. 모르면 '되묻기: '. 개인정보는 넣지 않는다.
[user]  대화 기록 (최근 2턴):
사용자: 실습실은 몇 시까지 열어?   챗봇: …평일 오후 9시까지 개방된다.
사용자: 주말에는?                  챗봇: …사전 신청한 학생만 이용할 수 있다.
마지막 질문: 신청은 언제까지 해야 해?
독립 질문:

챗봇 답변의 [1]은 지우고 넣는다 · 답변은 앞부분만 잘라도 된다

핵심 규칙 두 개: “답하지 말 것”(안 쓰면 모델이 답을 써 버려 검색어가 길어진다), “모르면 되묻기”(추측 방지).

인용 번호를 지우는 이유: 이전 턴의 [1]과 이번 턴의 [1]은 다른 출처다. 재작성에는 필요 없고 모델을 헷갈리게 한다.

위젯 출력 창의 “condense 프롬프트”를 펼치면 창 크기에 따라 이 프롬프트가 실제로 어떻게 바뀌는지 보인다.

규칙 기반 재작성 (키 없이)

  1. 대명사: 거기서 음료는? → 도서관 음료는?
  2. 생략: 주말에는? → 실습실 주말에는?
  3. 주제 전환: 그럼 딥러닝은? → 딥러닝 선수 과목은?
  4. 주제어를 못 찾으면 → 되묻기

한계: “거기는 몇 층에 있어?” → 실습실 ✗ (정답: 챗봇 답변 속 학과 행정실)

주제어는 사전(ENTITIES)에 있는 단어만 인식한다. 사전 밖의 주제(“주차장”)는 모른다.

한계 사례가 가장 중요하다. 규칙은 사용자 질문만 본다. 행정실은 챗봇 답변에만 나왔다. 틀린 재작성은 이후 단계를 모두 엉뚱한 방향으로 이끈다. 규칙 결과 “실습실 몇 층에 있어?”는 실습실 규정을 1위(5.06)로 가져오지만 층 정보가 없어, 챗봇은 되묻는다. 그런데 선택지가 실습실 이용 규정·FAQ·딥러닝 교과목이라 정작 학과 행정실이 없다.

LLM condense는 답변도 기록에 넣으므로 이 경우를 푼다. 위젯에서 재작성 방식을 바꿔 보여 준다.

창 N턴 → 턴마다 약 s + N·c자 · 창 없이 전체 → 대화 비용이 턴 수의 제곱으로

작으면 주제를 잃고, 크면 비용과 엉뚱한 연결이 는다. 4번째 질문은 창이 작을 때 되묻고(안전) 클 때 틀린다(위험). “창이 클수록 좋다”가 아니다.

실무: 최근 N턴 + 글자/토큰 예산(C1). 예산을 넘으면 오래된 턴부터 버리고 중간을 건너뛰지 않는다. 토큰은 한국어 1자 ≈ 1토큰으로 어림한다(1주차 토큰 카운터 복습).

발문: “학생이 학번을 말했다. 다음 턴 재작성 프롬프트에는 무엇이 실려 외부로 나가나?” → 가리지 않으면 매 턴 학번이 LLM 공급자에게 전송된다.

정규식은 형식이 정해진 정보만 잡는다(이름은 못 잡는다) → 안내문도 설계의 일부.

τ = 3은 C4에서 데이터로 다시 정한다. BM25 점수는 문서셋·질문 길이에 따라 달라 기준도 문서셋마다 다르다.

데모 · 원문 질문 vs 재작성 질문

시연 순서 (A/B 비교와 점수판은 오른쪽 실행 결과 창에 나온다)

  1. “실습실 이용” 턴 2: (A) 도서관·행정실·통학 버스 ✗, (B) “실습실 주말에는?” 근거 ✓ 1위. (A)의 추출식 답을 읽어 준다
  2. 턴 3: (A)는 근거 2위지만 1위가 기숙사 → 추출식 답이 “금요일 오후 6시”. hit@3만 보면 성공인데 답은 틀린다
  3. 창 3 → 1: 턴 3은 1턴 전 “주말에는?”에 주제어가 없어 원문 그대로 검색 → 기숙사 1위, 턴 4는 되묻기. 창 0이면 전부 원문과 같다
  4. 턴 4: 규칙은 “실습실 몇 층” ✗ → 재작성 방식을 LLM condense로 바꾸면 예시 재작성 “학과 행정실은 몇 층에 있나?” ✓. condense 프롬프트를 펼쳐 챗봇 답변 속 “학과 행정실”을 가리킨다
  5. “되묻기·개인정보”: 턴 1 되묻기, 턴 2 학번이 [학번]으로 가려짐
  6. 키가 있으면 “그럼 자연어 처리는?”을 직접 보내 LLM 재작성 결과를 규칙과 비교한다

관찰 질문

  1. “주말에는?”의 (A) 상위 3개는? 턴 3은 (A)도 2위인데 왜 위험한가?
  2. 창을 3 → 0으로 줄이면 턴 3·4는 어떻게 되나?
  3. 턴 4에서 LLM 예시는 “거기”를 무엇으로 보았고, 규칙은 왜 못 하나?
  4. “그럼 딥러닝은?”의 (A)는 문서는 맞는데 추출식 답은?
  5. “주차장은 어디야?”와 “점심 메뉴 뭐야?” 중 되묻기에 걸리는 것은?

1~3은 짝 활동 10분, 4~5는 휴식 후 전체 토론.

1번 핵심: hit@3는 “근거가 3위 안에 있다”만 본다. 1위가 틀리면 추출식·LLM 답이 1위를 따라갈 수 있다 → C3 2단계 hit@1.

4번: 문서를 찾는 것(검색)과 질문에 맞는 문장을 고르는 것(생성)은 다르다. 원문 “그럼 딥러닝은?”에는 “선수 과목”이 없어 추출식이 “3학점 과목” 문장을 고른다.

5번: 대화 초기화 후 “주차장은 어디야?”는 3.45 ≥ 3이라 답해 버리고(엉뚱한 추출식), “점심 메뉴 뭐야?”는 2.45라 되묻는다. 초기화하지 않으면 규칙이 앞 주제(휴학)를 붙여 버린다 — 규칙의 한계.

코드로 확인하기

import { chunk } from '/assets/js/core/chunker.js';
import { BM25 } from '/assets/js/core/bm25.js';

const corpus = await (await fetch('/assets/data/corpus/corpus.json')).json();
const extra = await (await fetch('/assets/data/w13/dept-docs.json')).json();
const docs = [...extra.shared.map((id) => corpus.documents.find((d) => d.id === id)), ...extra.documents];
const chunks = docs.flatMap((d) => chunk(d.text, { strategy: 'recursive', size: 300 })
  .map((c) => ({ id: `${d.id}#${c.index}`, text: `[${d.title}] ${c.text}` })));
const bm = new BM25().add(chunks);

for (const q of ['신청은 언제까지 해야 해?', '실습실 주말 신청은 언제까지 해야 해?']) {
  console.log(`Q: ${q}`);
  bm.search(q, 3).forEach((r, i) => console.log(`  ${i + 1}. ${r.id.padEnd(18)} ${r.score.toFixed(2)}  ${r.text.slice(0, 34)}…`));
}

정리

  • 대화형 RAG = 검색 앞에 재작성(condense) 한 단계
  • 규칙은 설명 가능, 답변 속 대상은 못 찾는다 · LLM은 풀지만 “답하지 말 것·되묻기”를 명시
  • 창 = 최근 N턴 + 글자 예산 · 효과는 원문 vs 재작성 hit@3
  • 인용은 턴마다 새로 · 모르면 되묻기 · 개인정보는 기록 전에 가리기

    kept.unshift(history[i]);
    used += c;
  }
  return { kept, used, dropped: history.length - kept.length };
}

const ENTITIES = ['가계 곤란 장학금', '장학금', 'RAG 과목', '딥러닝', '실습실', '도서관', '기숙사', '학과 행정실', '휴학'];
const PRONOUNS = ['거기서', '거기는', '거기', '그거', '그건'];
const MARKERS = ['그럼', '그리고', '근데'];

function lastEntity(text) {
  let best = null;
  for (const e of [...ENTITIES].sort((a, b) => b.length - a.length)) {
    const i = text.lastIndexOf(e);
    if (i >= 0 && (!best || i > best.i)) best = { e, i };
  }
  return best?.e ?? null;
}

function rewrite(history, q) {
  let topic = null;
  for (let i = history.length - 1; i >= 0 && !topic; i--) topic = lastEntity(history[i]);

  const pron = PRONOUNS.find((p) => q.includes(p));
  if (pron) return topic ? { query: q.replace(pron, topic), clarify: false } : { query: q, clarify: true };

  const marker = MARKERS.find((m) => q.startsWith(`${m} `));
  const body = marker ? q.slice(marker.length).trim() : q;

  if (!lastEntity(body) && topic) return { query: `${topic} ${body}`, clarify: false };
  return { query: body, clarify: false };
}

  const userLines = (history.match(/^사용자:/gm) ?? []).length;
  if (userLines > window) throw new Error(`기록이 ${userLines}턴이다. 창 크기 ${window}턴을 넘었다`);
  const lines = history.split('\n').filter((l) => /^(사용자|챗봇):/.test(l)).join('\n');
  if (lines.length > maxChars) throw new Error(`기록이 ${lines.length}자다. 예산 ${maxChars}자를 넘었다`);
  const q = text.split('마지막 질문:')[1]?.split('\n')[0].trim() ?? '';
  const places = [...history.matchAll(/학과 행정실|실습실|도서관/g)].map((m) => m[0]);
  const topic = places[places.length - 1];
  if (/거기|그거/.test(q)) return topic ? q.replace(/거기는|거기서|거기|그거/, topic) : `되묻기: “${q}”에서 무엇을 가리키는지 알려 줄 수 있나?`;
  return topic && !places.some((p) => q.includes(p)) ? `${topic} ${q}` : q;
}

const PII = [[/01[016789]-?\d{3,4}-?\d{4}/g, '[전화번호]'], [/(?<!\d)20\d{8}(?!\d)/g, '[학번]']];
const mask = (s) => PII.reduce((t, [re, tag]) => t.replace(re, tag), s);
const stripCites = (s) => s.replace(/\s*\[\d+(?:\s*,\s*\d+)*\]/g, '');

function buildCondensePrompt(turns, question, { window = 3, maxChars = 200 } = {}) {
  const recent = window > 0 ? turns.slice(-window) : [];
  let lines = recent.map((t) => `사용자: ${mask(t.user)}\n챗봇: ${stripCites(mask(t.bot))}`);
  while (lines.length && lines.join('\n').length > maxChars) lines.shift(); // oldest first
  const history = lines.length ? `대화 기록 (최근 ${lines.length}턴):\n${lines.join('\n')}` : '대화 기록: (없음)';
  const content = `${history}\n\n마지막 질문: ${mask(question)}\n\n독립 질문:`;
  return { system: SYSTEM, messages: [{ role: 'user', content }] };
}

for (const opts of [{ window: 3, maxChars: 200 }, { window: 1, maxChars: 200 }, { window: 3, maxChars: 60 }]) {
  const prompt = buildCondensePrompt(turns, '거기는 몇 층에 있어?', opts);
  console.log(`--- window=${opts.window}, maxChars=${opts.maxChars}\n${prompt.messages[0].content}`);
  try {
    console.log('→ mockLLM:', mockLLM(prompt, opts));
  } catch (err) {
    console.warn('✗ 규칙 위반:', err.message);
  }
}

// 비교: 기록을 가공하지 않고 통째로 보낸 프롬프트
const naive = { system: SYSTEM, messages: [{ role: 'user', content: `${turns.map((t) => `사용자: ${t.user}\n챗봇: ${t.bot}`).join('\n')}\n\n마지막 질문: 거기는 몇 층에 있어?` }] };
try {
  mockLLM(naive, { window: 3, maxChars: 200 });
} catch (err) {
  console.warn('가공 없이 보낸 프롬프트 ✗', err.message);
}
